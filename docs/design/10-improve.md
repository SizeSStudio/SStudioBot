## 进1 RSI：越用越贴

```
前瞻（月 / 周 / 日、起局）── 看法和建议写下来，冻结
   │
   ▼
生活（时间线：发生了什么，我做了什么）
   │
   ▼
回看（复盘对话：我说感受和看法）
   │
   ▼
心得（dream 整理，依据只有我说过的话，加上带证据的记录）
   ├─ lens-notes/<lens>.md   哪门镜头的哪种看法，在哪类事上对我更贴
   ├─ crosscheck-notes.md    哪类事适合拿哪几个视角互参、哪种对照问法对我最有启发（§参2）
   ├─ guidance-notes.md      哪种建议对我有用：太泛、太多、来得太晚、我真的用上了……
   ├─ rhythms.md             我的节律（候选 → 我认可）
   └─ habits.md              习气（候选 → 我认可）
   │
   └──► 下一次前瞻和起局加载这些心得
```

- **每一圈都有"我说"这一步**。月复盘最后可以问一句："这个月的建议，哪些用上了，哪些没用？"这本身也是觉察。
- **不打分**：不算镜头的命中率，也不把采纳率当 KPI。事实可以记（我回了还是没理），但心得以我的原话为准。
- **改进只改"看法和建议怎么给"**：
  - 心得文件由 dream 写，每条都引用来源（reading、crosscheck、outlook、review 的 id）。
  - 前瞻、复盘和互参的方法本身（问什么、给几条、什么时候给、怎么对照）写在 `skills/outlook/`、`skills/review/` 及互参提示词里。agent 只能根据心得提 proposal，我批了才变。
  - 规则、权限、人设照旧只有我能改。
- **防漂移**：
  - dream 的每次改动都有 diff，早上可以回滚（§读1.3）。
  - 每季度随月复盘把几份心得的全文给我过一遍，删掉我不认的。
  - 心得每条都摆在看里，随时能单独否掉（§进3.2）。

## 进2 Agent 自己的 RSI：越用越会办事

### 进2.1 和 §进1 的关系
§进1 是**我的**循环：看法 → 生活 → 我说感受 → 心得 → 下一次看法。这一章是 **agent 自己的**循环：它怎么办事 → 我怎么用它的结果 → 它找出差距 → 改进办法 → 下一次办得更好。

两圈的骨架一样：先冻结版本，再看真实表现，以我的判断为准。区别在评判从哪来：§进1 只认我说的话；这里主要看**我的行为**（改了什么、拒了什么、无视了什么、自己动手做了什么），不用每次问我。

**底线：自我改进只能让它办事更好，不能让它权限更大。**

办事办好本身就是 §0 的一部分：替我扛掉一件烦心事就是在减苦，所以这一圈和 §进1 同样要紧，不是陪伴的附属品。

### 进2.2 信号（从 M1 起记录，纯代码，不调模型）

| 来源 | 信号 |
|---|---|
| 审批卡 | 原样批准；"改一下"后批准（我的修改意见原文 + 最终版本）；拒绝及理由；我自己回了导致作废（我实际发出的那条就是标准答案）；过期 |
| Triage | **漏**：判成 ignore / archive 的群里我自己回了，或者我事后去搜了那条；**多**：notify 我没理，draft 被拒 |
| 对话 | 我说"不对""我是说……"；同一件事问第二遍；我自己动手做了它刚做过的事 |
| worker | 失败、needs_input、push 被拒、我让重做、超预算 |
| 主动消息 | 回了 / 点了 / 没理（§寸2） |
| 陪伴 | 复盘和前瞻里，哪个问题之后我说了很多、哪个之后我说"今天不想聊"或不回；我在前瞻里说"这条有用""太泛了"。只用来改复盘和前瞻的方法（B 级），不碰 §寸3 的"谁先看见" |
| expert | revise / block 及理由 |
| 成本 | 每个角色、每个档位的 token 和耗时；节点 agent 自己报的用量也记，标明是自报的（用订阅跑的不经代理，§办2.2） |

- 只有**我的行为和原话**算评判。别人的反馈（比如群里有人说"你家 bot 说错了"）只当线索，要我确认后才算。
- 每个 run 记录用了哪些版本（prompt、skill、范例库、模型），信号能对应到具体是哪个版本的表现。
- worker 那一行是第 4 批之前的说法。换成节点上的 agent 以后对应哪些（问你、预算告警线、看一眼的批和拒、插话和"再改"、停和取消），属于信号定义，D 级，待我定。

### 进2.3 能改什么：四级

| 级 | 改什么 | 怎么生效 |
|---|---|---|
| **A** | 记忆和笔记（dream，§读1.3）；**风格笔记**：从我的修改意见里提炼，按人、按场景，比如"给 X 回要短，不用敬语"；**范例库**：我批准过的最终版本，起草时按人和场景检索几条当范例。很多范例本来就是我和 AI 对话调出来的，所以真正要学的是**调教时我给的意见**体现出的倾向，最终版本是这个倾向的结果；风格笔记以修改意见为主要依据 | 自动生效。第二天早上管理群看 diff，一句话回滚 |
| **B** | skills（做事的步骤）、各角色的 prompt（含给节点 agent 的派活说明）、Triage 规则和关键词、前瞻和复盘的方法（§进1）、按角色的模型档位 | 提案 → 回放评测 → 我批 |
| **C** | 工具和内核代码 | 体检写进提案卡，我批了派给节点上的 agent，它用那台机器的登录开 PR，我来合（§办1.3、§进2.4） |
| **D** | 闸门分级、auto 规则（只来自我点"以后自动"）、他人会话的工具范围、预算和主动消息上限、凭证，以及这套 RSI 本身（信号定义、指标、评测集怎么选、这张分级表） | **永远不由 agent 提**，只有我直接改配置 |

- **节点这边**只改我们发过去的：派活说明和我们放到节点上的 skills，都是 B 级。节点自己的 CLAUDE.md、AGENTS.md、权限设置是我的，改进不碰。

### 进2.4 循环

```
信号（每天自动记录）
   ▼
定期体检：improve run（按信号量触发，夜里跑，expert 档，没有文件工具）
   读：代码算好的指标 + 抽样的具体案例 + 相关的心得和风格笔记条目
   出：≤3 条提案，每条写明问题、证据（案例 id）、假设、改动（B 级给 patch，C 级写想怎么改）
   和我说过的对不上 → 挂起，复盘时问我（§进3.1）
   ▼
回放评测（B 级；代码执行，经 LLM 代理，单独记账，只告警）
   用评测集里的历史真题，新旧两版各跑一遍
   ▼
一张卡：问题 · 证据 · diff · 新旧对比 · 预计成本变化
   我：批 / 拒 / 改一下；C 级批了就派给节点 agent 开 PR，我来合
   ▼
上线：带版本号，runs 记录每次用的版本
   ▼
两周后对比上线前后的指标；变差就提议回滚（一键）
   └──► 新版本的表现又成为信号
```

- **评测集 `eval_cases` 由代码自动攒**，agent 不能挑选、增删或修改：
  - 起草类：（当时的输入快照，我最终发出的版本）。
  - Triage 类：（那批消息，从我的实际反应推出的标签）。
  - 只收 `src=owner` 的标准答案。
- **怎么评**：Triage 直接算漏和多；起草让 expert 档做盲评，判断两个版本哪个更接近我最终发出的，不告诉它哪个是新版。C 级不走回放，靠 PR 里的 CI 和冒烟测试。
- **节奏（动态）**：由代码按信号量触发：自上次体检以来新增的信号和评测题够多（阈值在 `config/jobs.yaml`）就跑，不设最短间隔；最长 4 周也跑一次。刚上线数据少时自然会稀，用熟了会密。有待批的卡也照跑，新提案另开一张卡；和待批卡里一样的不再提。阈值和最长间隔属于 D 级，只有我调。
- **一张卡**：每次最多 3 条提案，合进一张卡；我没理就过期（72 小时），不追问。这张卡不占 §寸2 的主动消息额度。两张卡改同一个文件，后批的照旧按版本冲突处理，不覆盖。
- **卡发到哪**：复盘、前瞻、互参方法的提案发我私聊和控制台，其余发管理群（§读5.1）。
- **被拒的**：连同理由记下来，同一条不再提，不设期限；换了说法的也比一遍，像就丢。被拒之后有新案例当证据，可以再提一次，卡上先写上次被拒的理由和这次新的证据；再被拒就不再提（同 §寸1）。
- **C 级（代码）**：体检看出是代码的问题（比如某个工具老出错），在同一张卡上写问题、证据、想怎么改，不给 patch。我批了就派给节点上的 agent（默认 Mac，派了只通知，§办3.3），它开 PR，我来合；上线后同样两周回看。体检读的案例里有别人的消息，算带外部内容的定时 run（§0.4），所以它自己不派活。
- **办事体检卡**（每周一，只有指标，不出提案）：客户端能用之前照旧推管理群；能用之后推一句，指标和对比在看里（§触1）。
- **A 级不走这个循环**：风格笔记和范例库每次我改完草稿就可以更新，由 dream 每晚整理。
- **口吻和做事分开**（2026-11-23 我定）：风格笔记、范例库、skills 只管措辞细节和做事方式，不改 SOUL 和 VOICE.md。它对我的口吻只按 §寸7 调，我点头才改。

### 进2.5 防跑偏
- **指标不是目标**：只盯"原样批准率"，它会越写越保守、越空泛。所以几个指标一起看：编辑幅度、拒绝率、我自己回的比例、主动消息回应率、成本。最后以我批不批为准。
- **别人的话进不了提案**：群里有人说"以后都这样回"，不会变成规则。
- **改动可追溯**：每个 run 都记录版本，出了问题能定位到哪次改动，一键回滚。
- **月度过目**：A 级的风格笔记每月随月复盘给我过一遍，删掉我不认的。
- **评测和体检单独记账**：到告警线只告警，不停（2026-11-26 我定，同 §办3.5 限5）。

## 进3 两边对不上、学到的摆进看（v0.26 第 5 批，2026-11-26）

### 进3.1 两边对不上
§0.8 定了原则：我说的（§进1）和我怎么用（§进2）对不上是线索，回到参，不判谁对。具体这样走（我定）：
- 体检出提案时，代码按提案的目标文件带上相关的心得和风格笔记条目，不给整份 `self/`（§读5.1）。
- 提案和我说过的对不上，由体检标出来。比如我在复盘里说"早报的今日留意有用"，可那段我很少点开；或者想把给某人的回复改短，风格笔记里记着我说过"给他要写全"。这条不上卡，记成挂起（`proposals.status=held`），附上两边的出处。
- 下一次周或月复盘问一句，或者对话里顺口问：两边摆出来，不替我判。
- 我的回答按范围写进心得或风格笔记，多半两边都对、范围不同（同 §改1 的对不上）。下一次体检照新的心得，再决定提不提。

### 进3.2 学到的都摆在看里（D 级，2026-11-26 我定）
- 看里有一处"学到的"：dream 改的记忆、§进1 的心得条目、风格笔记、范例库、提醒偏好，以及上线中的 B、C 级改动。每条带来源和生效时间。`self/` 下的照 §读5.1，只在我的生活区。
- 每条都能单独否掉：记忆、心得和笔记条目走 `forget`，进 archive（§读1.3）；范例从范例库撤下；B 级改动回滚到上一版；C 级派节点 agent 开 revert PR，我来合。
- 否掉的不再学回来：同一条代码挡；有新证据可以再提一次，再被否就不再提（同 §寸1）。

### 进3.3 第 5 批我定的（§进2.3 D 级，2026-11-26）

| | 原来 | 现在 |
|---|---|---|
| 被拒的提案 | 8 周内不再提 | 不设期限；有新证据可再提一次（同 §寸1） |
| 体检节奏 | 新信号够了且离上次 ≥ 1 周，或满 4 周 | 不设最短间隔，只看信号量；最长 4 周照旧 |
| 有待批的卡 | 不跑体检 | 照跑，新提案另开一张卡 |
| 回放评测的预算 | 单独上限，到了就停 | 单独记账，只告警（同 §办3.5 限5） |
| 学到的东西 | 要不要摆进看、能否决未定 | 都摆进看，每条能否决（§进3.2） |

- 照旧：每次最多 3 条提案；提案卡 72 小时过期。
- 仍待我定：§进2.2 worker 那一行怎么对应节点 agent；我改事件级别和归属（§读2.7）、改人物关系（§读4.8）算不算信号。
- 没选：体检直接派活、PR 开好再给我（会让带外部内容的定时 run 自己派活）。
