## 办1 角色与 harness

### 办1.1 harness：干活交给节点上现成的 agent，对话角色用 pi

**分工**

| 角色 | harness | 原因 |
|---|---|---|
| 干活（原 worker） | **节点上现成的 agent**：Claude Code、Codex、pi 走各自的官方接口，别的走 ACP（客户端 acpx）（2026-11-26 定，§办3.2） | 不自己造干活的栈。各 agent 自带工具、权限设置和本机登录；常用的三个走官方接口，拿得到插话、续接这些细能力 |
| lens | **三件套**：脚本排盘、pi 解读、只读 `kb_read`；不走 SDK worker | 排盘是确定的，不需要内置工具；解读用对话角色同一套 pi |
| 迁完之前的 worker | **Claude Agent SDK** | 要内置工具、skills。迁完以后服务器上的 worker 就是"服务器节点上的 Claude Code"（§办3.2） |
| 主 agent、reflect、起草、Triage、expert、dream | **pi 1.5.2**（`createAgentSession`，在核心进程里跑，每条 lane 一个常驻 session），2026-11-16 P0 对比后定（§附2） | 见下 |

**对话角色为什么用 pi**（P0 实测：`probes/RESULTS.md`）
- **SDK 的长处它们用不上**：这些角色不用任何内置工具，不要 sandbox，审批走提交式，也不用 `defer`。现在为了用 SDK，反而要花力气把东西关掉（`tools: []`、`settingSources: []`、一长串环境变量），而且每个 run 都要起一个 CLI 子进程。
- **红尘里修的核心是"上下文怎么拼"**：本月和本周的前瞻、时间线片段、认可过的习气和节律、心得。pi 能直接控制每次请求带什么：`context` 事件每次调模型前都能改消息，`before_agent_start` 能换 system prompt，`session_before_compact` 能自己写压缩摘要，保证发心、本月留意这些锚点在压缩后还在。SDK 里压缩基本是黑盒，只能事后拿摘要。
- **不绑厂商**：pi 原生支持多家协议。chat 档如果用的不是 Claude，就不必经过 Claude Code 那套为 Claude 调过的提示词和工具约定。
- **能读懂**：pi 的核心很小，和"代码自己能完全读懂"的目标一致。
- **轻**：pi 在核心进程里只发 HTTP 请求。SDK 每个 run 要起一个 CLI 子进程，实测常驻 230～320 MB，冷启动 1～3 s。对单机部署（§底1.3）来说，这一条分量很重。

**代价和对策**
- pi 迭代快：包名从 `@mariozechner/*` 迁到了 `@earendil-works/*`，事件也改过名。对策：锁定版本，所有调用都包在一层 `Runner` 接口后面。
- pi 没有权限系统（1.5.2 起有可选的 MCP 扩展，我们不用）：我们的工具本来就是自己写的 TS 函数，直接注册就行；闸门放在工具包装层（见下）。
- pi 会从 `~/.pi`、`.pi/` 自动发现扩展、skills 和 `AGENTS.md`：✅ 已核实能关掉。做法如下：
  - `DefaultResourceLoader({ noExtensions, noSkills, noPromptTemplates, noThemes, noContextFiles, systemPrompt, extensionFactories: [我们的] })`，再配上私有的 `agentDir`。
  - 模型写在 `agentDir/models.json` 里：provider `sbot`，`api: anthropic-messages`，`baseUrl` 指向 LLM 代理，`apiKey: "$SBOT_RUN_TOKEN"`（从环境变量插值，令牌不落盘）。
  - `noTools: "builtin"` 加上 `customTools`。
- **工具 schema 只写一次**：用 zod 写，SDK 那边直接用；给 pi 时经 `z.toJSONSchema` 转成 JSON Schema，再包一层 `Type.Unsafe`。
- 两套会话格式：`sessions` 表记录 `harness` 和 `session_ref`，滚动换代时两边各自处理。

**与 harness 无关的一层**（两边共用，换 harness 不动它）
- `Runner.run({ lane, role, tier, session_ref, input, tools, budget })` → `{ output, side_effects, usage, session_ref, stop }`。**Runner 只留这一个接口**（原来对话角色、SDK worker、节点适配器各一套）：pi、SDK、节点上的各家适配器（§办3.2）都实现它，上层不认 harness。
- **工具只定义一次**：一个 TS 函数加一个 schema。适配到 SDK 时包成 in-process MCP，适配到 pi 时用 `customTools` / `registerTool`。
- **闸门放在工具包装层**：我们自己的工具，在函数执行任何副作用之前先过闸门（分级、提交审批），哪种 harness 都一样生效，也不依赖 hook 出错时的语义。迁完之前的 SDK worker，内置工具（Bash、Edit……）另外靠 SDK 的 `PreToolUse`。节点上的 agent 不挂我们的闸门：按它自己的权限设置跑，来问时转成看一眼卡（§办3.3）。
- 走我们的 LLM 代理的请求（§办2.2）用每个 run 的临时令牌，只有核心进程里的 run 和服务器上迁完之前的 worker 走它；节点 agent（含远端节点）只用节点自己的登录和额度，不经代理、不拿 run 令牌（我定，2026-11-27，§办3.2）。

#### 办1.1.1 Claude Agent SDK 的用法（迁完之前的 worker；节点 agent 不走这套。按官方文档核对过）

| 需求 | 用 harness 的什么 | 自己写的部分 |
|---|---|---|
| agent loop、工具调用 | `query()` | 无 |
| 会话续接 | `resume` | session key ↔ sdk_session_id 映射；resume 失败时的兜底（§底1.2） |
| 上下文压缩 | 自动 compaction + **`PostCompact` hook**（拿到 `compact_summary`） | 摘要写进 journal |
| 出口闸门 | **`PreToolUse` hook**，设 `onFailure: "block"`（需要 TS SDK ≥ 0.3.317） | 分级、审批、计数 |
| 运行中途审批 | PreToolUse 返回 **`defer`** → `stop_reason: "tool_deferred"` → 不带 prompt 地 resume，hook 再次触发并给出 allow/deny | 审批状态机（§底3.2） |
| 自定义工具 | in-process MCP（`createSdkMcpServer` + `tool()`），工具代码在核心进程里执行 | 记忆、任务、消息、审批、定时器 |
| 干活的工具 | worker 用内置 Read / Edit / Write / Bash / Grep / Glob + `sandbox` | 无 |
| 后台长任务 | — | **Task Engine**。harness 自带的后台 subagent 会随进程一起消失，不用它 |
| 搜索 / 抓取 | 内置 WebSearch / WebFetch | 探测不通时的兜底工具（§办2.4） |

**harness 使用纪律**
- **权限模式统一用 `dontAsk`**，不传 `canUseTool`。官方文档写明：被 `allowedTools`、allow 规则或权限模式自动批准的调用**根本不会到 `canUseTool`**，所以 `canUseTool` 不适合做闸门。在 `dontAsk` 下，任何需要询问的调用都直接拒绝，不会有调用挂着等回调。
- **闸门只放在 `PreToolUse`**，并且设 `onFailure: "block"`。hook 默认出错放行，`block` 之后出错就拦截。
- **工具可见性**：
  - 用 `tools: [...]` 明确列出要哪些内置工具，再用 `disallowedTools` 写裸工具名兜底（裸名会把工具定义从请求里删掉）。
  - `allowedTools` **只用来自动批准**我们自己的 MCP 工具（`mcp__sbot__*`）。它本身不限制模型能用哪些工具。
- **`defer` 的实际行为**（P0 实测，SDK 0.3.325 / CLI 2.1.325，见 `probes/RESULTS.md`）：
  - 恢复方式：`query({ prompt: "", options: { resume } })`。传空的 AsyncIterable 会失败（`tool_deferred_unavailable`）。恢复后同一个 `tool_use_id` 会再过一次 hook。
  - **并行调用时 defer 并没有被忽略**（和原来的假设相反）：模型一轮里发两个要审批的调用，hook 两个都返回 defer，结果只报告其中一个，另一个**静默丢失**（不执行，也不算拒绝）。
  - **对策（已验证）**：闸门按 session 加一把锁，同一时刻只允许一个调用 defer（同步写入，在任何 await 之前），其余直接 deny，理由写明"这个没做，等当前审批结束后重试"。模型会在批准后自己重试。需要审批的工具照旧不放进 `allowedTools`。
- **`settingSources: []`**：任何 run 都不读磁盘上的 settings 和 CLAUDE.md（默认值是"全部来源"，worker 在别的仓库的 worktree 里干活时会加载那个仓库的配置）。system prompt 由我们自己拼。skills 用 `plugins` 选项加载，**每个 run 必须同时传 `skills` 白名单**（P0 已验证，见下）。
  - 镜头打包成只读插件 `/opt/sbot/plugins/sbot-lens`（root 所有，worker 只能读；`deploy/lens/build.sh` 从 Mac 上的 skill 源和 kb 构建，把写死的 Mac 路径改成安装路径）。放在 agent-home 外面，worker 读得到但改不了。
  - `settingSources: []` 时 CLI **仍然会带上它自带的插件和 skill**（`deep-research`、`dataviz`、`claude-api`、`update-config` 等 16 个，init 里都会列出来）。`skills: [...]` 白名单生效后，模型看到的列表只剩白名单里的；调白名单外的 skill，Skill 工具直接报错 `not in this session's skills allowlist`。所以 `skills` 永远显式传，不用 `'all'`。
  - init 里的 `skills` 列的是"发现了哪些"，不是"模型能用哪些"，不能拿它判断白名单。需要的设置通过 `settings` 选项传入（如 WebFetch 的 `skipWebFetchPreflight` 和 `env.HTTPS_PROXY`，见 §底3.6）。**不传 `cleanupPeriodDays`**：`settingSources: []` 下没有任何来源提供它，CLI 就跳过转录清理（P0 实测），挂起的会话不会被清掉。旧转录随任务目录由核心 GC 删除。
- **env 从零构造**：`env` 是整体替换，不是合并。每个 run 只给：
  ```
  PATH, HOME, LANG, TZ                   # 显式给，不继承宿主
  CLAUDE_CONFIG_DIR = <按角色/任务独立的目录>   # 不碰宿主的 ~/.claude
  ANTHROPIC_BASE_URL   = http://127.0.0.1:7811/llm     # LLM 代理（§办2.2）
  ANTHROPIC_AUTH_TOKEN = run_<随机>                    # 这个 run 的临时令牌（Bearer）
  ANTHROPIC_MODEL      = sbot-<tier>                   # 档位别名，由代理换成真实模型
  ANTHROPIC_DEFAULT_HAIKU_MODEL / _SONNET_MODEL / _OPUS_MODEL = sbot-light / sbot-<tier> / sbot-<tier>
  CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS = 1
  CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC = 1
  CLAUDE_CODE_DISABLE_CRON = 1           # 另外也不暴露 CronCreate 一类工具
  ```
- **锁定版本**：SDK 和 CLI 都锁定版本。升级时先跑一遍 P0 探针脚本，全部通过才切换。
- **不使用 auto mode**：它的分类器只支持特定模型，第三方端点用不了。

**token 开销**：对话角色用精简的自定义 system prompt，只挂自研工具；只有 worker 用 `claude_code` preset 加内置工具。

### 办1.2 主 agent（chat 档）

人设和规则来自 `AGENTS.md`、`SOUL.md`；关于我的事实来自 `USER.md`、`MEMORY.md`（索引）。每轮自动召回的片段附在 **user 消息**里，不放进 system。

**工具按会话类型给，不按信任模型给**：具体哪些工具在哪类会话里给，以 §底3.1 的三列权限表为唯一出处（我亲手发、定时或系统触发、他人会话），这里不再抄。

- **定时、系统触发的 run，工具和我亲手发时一样**（我定，2026-11-27），只减去 §读5.1 本来就禁的：不能用工具整份读或改 `self/`、命盘、出生信息，所以 `self_profile`、`self_page`、`bash` 和读写文件不给（`bash` 能整份读 `self/`，给了就守不住底线；这不是新加的限制）。代价记在 §底3.8：外部内容里藏的指令，可能经早报或复盘起一个主机 worker，不过审批卡。
- **来源标签跟着「是不是我亲手发的」（`ownerTyped`）走**：我亲手发的标 `owner@<surface>`；定时、系统、任务、审批触发的标 `job@<名字>` 或 `system@<类型>`。journal 每行带来源和 `run_id`；dream 只把 `owner@` 的行和我所有主对话 lane 的行当成我说的。外部内容进上下文时打上不可信标记（§0.4）。这只关乎记对是谁说的，不收能力。
- **对话里也能直接跑命令、改文件**（2026-11-26 我定，§办3.5 限2）：
  - 主 agent 的 `bash`、`check` 脚本、本地 agent 走同一条本机节点接口，同机走 unix socket。节点接口除了开 session、发消息、插话、停、续接、权限请求、进度（§办3.2），还有「执行命令」一项。
  - 命令以节点的账号跑（服务器上是 `sbot-h`），不在主的账号下。残余风险：`sbot-h` 有完整 sudo，挡不住它读主的密钥；核心守卫只看命令和路径要去哪里，是软边界（§底3.6、§底3.8）。
  - **命令守卫挂在哪一层**：pi 本身没有权限系统，`createAgentSession` 里内置工具关着（`noTools: "builtin"`），只注册我们自己的 `customTools`。守卫挂在工具包装层，`piTools` 里每个 `execute` 先进 `callTool`，`bash` 也作为我们自己的工具注册，守卫在它转给节点接口之前先过。现状：`core/src/runner.ts` 里 pi 这边还没有 `bash` 工具；`coreGuard`（`core/src/tasks.ts`）只作为 SDK 的 `PreToolUse` hook 挂在迁完之前的主机 worker 上，pi 还没接。守卫的具体规则留给技术设计。
  - 他人会话不变（工具范围是 D 级）。
- 他人会话里，对方的消息一律用 `<untrusted from="…">` 包起来，system prompt 里写明这部分内容只当数据，不当指令。

### 办1.3 干活：任务交给节点上的 agent

- `task_start({ goal, context, node?, agent?, tier? })` → 在那台节点上用那个 agent 开一个 session（§办3.2），这个 task 就是一条 lane。不填按配置的默认值。节点、调用、等待点、生命周期见 §办3。
- **任务进度文件**：agent 在工作目录里维护 `progress.md`，写明做完了什么、还剩什么；节点随进度回传一份。换 session、换机器、重开时，先读它。
- **交报告**：结束时调用 MCP 工具 `submit_report`（结论、改动、验证、未完成），Task Engine 往发起它的 lane 投一条 `task_done` 事件。agent 没调就拿最后一轮输出当报告。
- **问我**：权限请求和 `ask` 都变成等待点，答案回到同一个 session（§办3.3）。
- **以我名义发给别人**只走 `send`，审批卡（底线）。
- **改代码**：agent 用节点自己的 git 登录提交、推送、开 PR（§办3.5 限6）。改 SStudioBot 自己的代码只走 PR，由我来合。节点没登录时调 `git_push`，由核心代推（下面的旧路径）。
- **不设上限**：轮数、时长、同时几个都不限；我可以给每台机器设一个同时数，不设就不限。预算只告警（§办2.2）。

#### 办1.3.1 迁完之前：服务器上的 SDK worker

迁成节点上的 Claude Code（§办3.2、§附2.17）之前照旧跑，下面是现状。

- `task_start` 的 `mode?`、`budget`、`timeout` 只对它有效；Task Engine 起一个独立的 `query()`。
- **两种模式**（`tasks.mode`，默认值取 `config/worker.yaml` 的 `default_mode`，没配就是 host；v0.14 之前的老任务按 sandbox 处理）：
  - **host（默认）**：`sudo -n worker-exec --host` 用 `systemd-run --pipe --wait` 起一个 transient **service**（`sbot-workers.slice`，`MemoryMax=6G`，`RuntimeMaxSec=5h`），以 `sbot-h` 身份运行，cwd 是 `/srv/data/sbot-h/tasks/<id>/`。用 service 而不用 scope，是因为 scope 会继承核心的挂载命名空间（`ProtectSystem=strict`），sudo 装不了东西；service 由 pid 1 起，在宿主机的命名空间里。stdio 经 `--pipe` 透传，SDK 照常工作；环境变量写进一个 root 才能读的 `EnvironmentFile`（`Environment=` 能被任何本地用户通过 D-Bus 读到，里面有 run token）。杀掉 systemd-run 不会停掉 unit，所以 worker-exec 捕获 TERM 信号，自己 `systemctl stop`。
    - 没有 bwrap，不经过出网代理，也不受 `SBOT_W` 链限制，公网、DNS、tailnet 全通，有完整 sudo（`/etc/sudoers.d/sbot-h`）。HOME `/srv/data/sbot-h/home` 持久保留：`~/.local/bin`、CLI 登录状态、ssh key（`install.sh` 生成，公钥由我加到要登录的机器上）。
    - ssh 主机：核心在每次 run 之前按 `worker.yaml` 的 `ssh_hosts` 生成共享目录里的 `ssh_config`（`BatchMode`、`StrictHostKeyChecking accept-new`），worker-exec 再把它复制成 sbot-h 自己名下的 `~/.ssh/sbot_hosts`，由 `~/.ssh/config` include 进来。不能直接 include 共享那份，因为 ssh 只认属主是本用户或 root 的配置文件，而核心改不了属主。worker 直接 `ssh mac` 就行。`host` 填 tailnet IP：这台服务器没开 MagicDNS（`--accept-dns=false`），`*.ts.net` 的名字解析不了。
    - **核心守卫**：一个 PreToolUse hook 拦截 Bash 命令，以及 Read/Write/Edit/Glob/Grep 的路径参数中指向核心位置的调用（`/srv/sbot`、`secrets.env`、`/run/sbot`、`/proc/*/environ`、lark-cli）。只看工具要去哪里，不看写进去的内容，所以改本仓库里提到这些路径的文档照样能改。worker 规则里也写了"有 sudo 也不碰"。这是软边界（§底3.6）。
  - **sandbox**：就是下面原来那套，以 `sbot-w` 用户运行。Linux 上才有，可选：碰到不可信内容（陌生网站、别人的仓库、别人发来的文件）先问我一句，我说进沙箱才用（§办3.3）。
- **skill 和 CLI（两种模式都有）**：核心在每次 run 之前把 `config/skills/<名字>/` 复制到 `/srv/data/sbot-shared/worker-plugin/skills/`（全员可读、只有核心能写；先建一份新的再换上去），用 SDK 的 `plugins` + `skills` 选项加载。`skills` 始终显式传：默认是 `config/skills` 下的全部，也可以在 `worker.yaml` 里列名字或写 `all`（`all` 会连 CLI 自带的也打开）。`worker.yaml` 的 `path` 通过 `settings.env.PATH` 加在 PATH 前面。
- **sandbox 模式的隔离**（§底3.6）：
  - 以 `sbot-w` 用户运行（P0 已验证）：SDK 的 `spawnClaudeCodeProcess` 把 CLI 改成 `sudo -n /usr/local/lib/sbot/worker-exec <args>`。这个 root 所有的包装脚本校验 cwd 是 `sbot-w` 的任务目录，再用 `systemd-run --scope`（`sbot-workers.slice`，`MemoryMax=1G`）+ `setpriv` 切到 `sbot-w` 去跑锁定版本的 CLI（`/opt/sbot/claude-code/<ver>/claude`）。sudoers 只放行这个脚本和 `task-mkdir`，环境变量只保留 `ANTHROPIC_*`、`CLAUDE_*`、`LANG`。in-process MCP 和 hook 走 stdio，跨 sudo 照常工作。安装文件在 `deploy/worker/`。
  - bash 套 SDK `sandbox`（bubblewrap），`failIfUnavailable: true`、`allowUnsandboxedCommands: false`。
  - 工作目录 `/srv/sbot-w/tasks/<id>/`，`CLAUDE_CONFIG_DIR` 也放在里面。`HOME` 固定为 `/srv/sbot-w/home`，不放在任务目录里（sandbox 会屏蔽可写路径下的 shell rc 文件，放进去 bash 每次都报 `.bashrc: Permission denied`）。
  - PATH 里**没有 lark-cli**，也没有任何凭证（host 模式同样不给，对飞书的动作仍然走核心工具和审批）。
- **对外动作走核心工具**：比如 `feishu_doc_write`、`git_push`。PreToolUse 返回 `defer`，任务进入 `waiting_approval`，批准后 resume（§底3.2 B）。
- **核心代推**：worker 只在自己的 worktree 里提交，没有 push 凭证。批准后核心从 worker 的 worktree 把分支 fetch 到自己的镜像仓库，带 `core.hooksPath=/dev/null` 再推送。**核心从不在 worker 目录里执行 git 命令**。
- **问人**：以 `needs_input` 结束，由主 agent 来问我；拿到答案后 resume 同一个 session。
- **现有上限**（代码里还在，按 §办3.4 去掉，见 §附2.17）：轮数、`RuntimeMaxSec`、无输出看门狗；每会话 3 个、全局 5 个未结束任务；同时跑的进程默认 1 个。

### 办1.4 Expert（expert 档，无工具）
- **待审材料由代码直接塞进 prompt**（草稿、diff、计划、日志），不给任何读文件的工具；`maxTurns` 很小。
- 输出 `{ verdict: pass|revise|block, issues[], suggestion }`。
- 触发条件见 §办2.5。

### 办2.2 LLM 代理（凭证代理）

所有 run 的模型请求都打到核心里的代理 `127.0.0.1:7811/llm`，再由代理转发到真实端点：

1. **校验令牌**：每个 run 一个随机令牌，绑定 `{run_id, tier, requester, 预算, 过期时间}`。run 结束时令牌作废。
2. **换模型**：把请求里的 `sbot-<tier>` 换成该档配置的真实模型名。改配置后下一个请求就生效，不用改 env。
3. **加凭证**：按端点配置加 `x-api-key` 或 `Authorization: Bearer`，原样转发（包括流式）。
4. **计量**：从响应的 `usage` 里记 token，乘上 `models.yaml` 里的价格表，写进 `usage` 表，按 run / 任务 / 请求人汇总。
5. **预算只告警，不停**（2026-11-26 我定，§办3.5 限5）：run、任务或全天用到告警线时，Sentinel 发一条告警，请求照常转发。
   - 令牌无效、过期或越档仍然拒绝，这是鉴权，不是预算。**状态码用 403 `permission_error`，不要用 429。** P0 实测（2026-11-16）：返回 429 时，Claude Code 会退避重试，每个 query 大约重试 10 次、拖 2.5～3 分钟才以 `api_error` 结束；返回 403 时立刻失败。CLI 报的文字（"Failed to authenticate"）不可靠，以代理账本为准。
   - 代理的计量要算上**上游自己加的系统提示**：实测一个 2 token 的请求也会带出 2～3k 的 cache 读写。
   - 节点 agent 用本机登录和订阅时不经代理，不计量（§办3.2）。

这样一来：
- SStudioBot 的 key 只存在核心进程里。
- 拿到令牌的也只能在本档、在 run 存活期间调模型。
- 用量按 run、任务、请求人记账，告警不依赖模型自觉。

### 办2.3 配置（`config/models.yaml` + `/srv/sbot/secrets.env`）

```yaml
endpoints:
  main-gw:   { base_url: https://..., auth: x-api-key, key_ref: MAIN_GW_KEY }
  expert-gw: { base_url: https://..., auth: bearer,    key_ref: EXPERT_GW_KEY }

tiers:
  chat:   { endpoint: main-gw,   model: <待定>, effort: medium, price: { in: ?, out: ? } }
  work:   { endpoint: main-gw,   model: <待定>, effort: medium, price: { in: ?, out: ? } }
  light:  { endpoint: main-gw,   model: <待定>, effort: low,    price: { in: ?, out: ? } }
  expert: { endpoint: expert-gw, model: <待定>, effort: high,   price: { in: ?, out: ? }, daily_alert: 20 }   # 只告警（原 daily_limit，旧键照认）

capabilities:            # 由探针脚本填写，也可以手动覆盖
  chat:   { vision: ?, forced_tool: ?, server_web_search: ?, web_fetch_ok: ?, context: ? }
```

- `secrets.env` 权限 600，属主 `sbot`，不进 git。
- **备用模型（可选，默认不配）**：档位下加 `fallback: { endpoint?, model, price? }`。代理看到主模型报**用量上限**（HTTP 错误，或 200 流里的第一条 error 事件）时，把这次请求原样改发给它；普通 429、5xx 不切，那些等一等就好。切换只发生在这一次请求，会话和 `runs.model` 不变。
  - 可能换计费端点，所以由我决定填不填。记账照旧，账本记实际用的端点、模型和价格（`price` 不写就用本档的），主模型那次失败也记一行（0 token）。
  - 备用也失败时，调用方拿到的还是主模型的上限错误，走自己的重试规则。没配 `fallback` 时响应原样透传，不改内容；只在需要认出用量上限的错误时才看错误体或流里的第一条 error 事件。
  - 限制：带 thinking 签名的历史换模型会被拒（§办2.4），这种请求等于没切成。
- **M0～M2 阶段**：直接改文件，加上飞书 `/model` 卡片（只能看配置、切换档位里的模型名、触发探针）。控制台里的「模型」页放到 M3。

### 办2.4 按能力降级

| 能力缺失 | 降级方式 |
|---|---|
| `vision: false` | 用一个支持 vision 的档位先把图片转成文字；哪档都不支持就只存图，回复里说明看不到 |
| `forced_tool: false` | 结构化输出改用"提示词约束 + 代码校验 + 失败重试一次" |
| `server_web_search: false` | **默认用模型自带的搜索**（WebSearch 的服务端工具由转换层映射）。P0 实测 上游的 claude 档原样支持 `web_search_20250305`。对话角色在 pi 上，没有内置 WebSearch：核心的 `web_search` 工具就照 Claude Code 的做法，经 LLM 代理发一次带 `web_search_20250305` 的 Messages 调用，把结果整理后返回。哪档不支持，再换成自接搜索 API |
| `web_fetch_ok: false` | P0 实测：关闭非必要流量后 WebFetch 仍可用，但默认会直连目标网站和 api.anthropic.com（域名检查）。worker 里固定 `skipWebFetchPreflight: true` + `settings.env.HTTPS_PROXY` 走核心出网代理（§底3.6）。对话角色（pi）用自研的 `web_fetch`（核心抓取 + 转 markdown），同样走出网代理的白名单和日志 |

**换模型后会话怎么办**：thinking 块的签名换了模型就会失效。所以某个档位换模型后，这一档的滚动会话在下一个 run 自动开新 session，旧会话的要点用摘要带过去。

**降级换模型时**（比如备用模型、换档，§办2.3）：同一个 session 里换模型前，先把历史里旧模型的 thinking 块剥掉再发，免得签名对不上被拒。工具调用进行到一半（有 `tool_use` 还没收到结果）时怎么处理，由探针定（`docs/tech/08-probes.md` P10）；定之前等这轮工具结果回来再换。

## 办3 节点与派活（v0.26 第 4 批，2026-11-26；2026-11-27 补）

方向（我定）：多端、开放，尽量复用现成的东西；除非我说过，不做限制，最多看一眼（§0.4）。取代更早的 ssh 派活（派到 Mac 的老做法）。参考实现：Paseo；11-27 的补充参考了《Agent 工作台产品设计与系统架构调研》（§附1 参考）。

### 办3.1 主和节点

- **主**（hub）：核心进程、SQLite、`config`、`agent-home`、LLM 代理、飞书连接。**同一时间一个主，Linux、Mac、Windows 哪台都能当。** 数据只有一份；换主 = 新机器装核心、从备份恢复、节点重连。
- systemd unit、`sbot-deploy` 自动上线、bwrap 沙箱、iptables 是 Linux 主上的可选件，不是前提（§底1.3）。
- **主用单独的系统账号跑**（或密钥放系统钥匙串）：和 agent 同账号的话，agent 读得到主的 `secrets.env`（底线：密钥只写不读）。
- **节点**（node）：装了节点程序的任何一台，包括主所在那台。
  - 节点主动连主，主不连节点。和客户端一样经中继、Noise 握手（§触6.7）。
  - 配对同 §触6.7（`sbot pair --node`、已配对设备上出码、飞书 `/pair node`）：私钥不离开节点，主只存公钥；角色是 `node`，接活、报进度，批不了审批、答不了看一眼；在主上删。
  - 上报：在线、节点程序的版本和各适配器的能力（§办3.2）、本机有哪些 agent、正在跑的 session、订阅的剩余额度（agent 报得出的）、我给这台设的同时数（可选）。
  - **协议只加不减**，同 §触6.2：节点连上时报版本和能力，太旧就提示升级，不猜着跑（借 Paseo、Herdr）。手机、Mac、Windows 上的节点一定会和主的版本不一致。
- Windows 微信机并进节点：微信 reader 和 sender 是那台节点上的能力（§触3）。迁完之前连接照旧。
- **备份**：任何节点都能存一份，默认 Mac；不用第三方存储（§底1.3）。

### 办3.2 怎么调 agent：常用的走官方接口，其余走 ACP

最常用的三个走官方接口，拿得到 ACP 没有的插话、续接、回退（2026-11-26 我定）；别的为了好适配走 ACP。节点程序里每种一个适配器，对主是同一个接口：开 session、发消息、插话、停、续接、权限请求、进度。

| agent | 接口 | 插话 | 权限请求 | 续接 |
|---|---|---|---|---|
| Claude Code | Claude Agent SDK，流式输入 | 往进行中的输入里推消息 | `canUseTool` | `resume` |
| Codex | `codex app-server` | `turn/steer` | `item/commandExecution/requestApproval`、`item/fileChange/requestApproval` | `thread/resume` |
| pi | `pi --mode rpc`（JSONL） | `steer` | 没有权限系统，直接跑 | `--session <文件>` |
| 其他 | ACP，客户端 **acpx**；不够用换 ACP TS SDK | 没有，排到下一轮 | `session/request_permission` | `session/load` → `unstable_resumeSession` → 新 session 读 `progress.md` |

- **适配器报能力**：插话、续接、回退、权限请求、提问，各报能不能做；主和客户端只看能力，不认 agent 的名字。做不到就照实显示（比如 pi 不会来问），不拿自动回答冒充（借 T3 Code）。每家一个翻译层，转成同一组事件，不丢、不乱序（借 Cindy）。Claude Code 自带的提问工具（`AskUserQuestion`）也转成「问我」（借 Orca）。
- 官方接口、acpx、ACP SDK 都锁版本，升级先跑探针（`unstable_` 开头的会变）。
- 一个任务一个 session，`session_ref` 存在任务上。
- 我们的工具（`submit_report`、`ask`、`send` 等）作为 MCP server 挂进 session，各家的挂法待核实：Claude SDK 的 `mcpServers`、Codex 的 MCP 配置、pi 的 MCP 扩展（`--mcp-config`）、ACP `session/new` 的 `mcpServers`。
- Claude Code 读节点自己的 settings（`settingSources` 含 user / project / local），按它自己的权限规则放行，规则外的才到 `canUseTool`。旧 worker 的 `settingSources: []` 不变（§办1.1.1）。
- **登录各用各的**（§办3.5 限6）：agent 用节点自己的登录、订阅和设置。SStudioBot 的密钥一律不给（底线）。远端节点只用自己的登录和额度，不走主的 LLM 代理，也不给 run 令牌（我定，2026-11-27）；用量只能看节点报上来的剩余额度。
- 现在的 SDK worker 迁完就是"服务器节点上的 Claude Code"，`sbot-h` / `sbot-w` 两种账号照旧可选（§办1.3.1）。
- **反向开放**：我们的工具作为 MCP server，给任何 agent 用，包括我在 Mac 上自己开的。新入口，默认关，我确认才开。

### 办3.3 看一眼和等待点

- **权限**（我定）：agent 按它自己的权限设置跑。它来问时（各家的权限请求见 §办3.2 的表），转成一张看一眼卡，带上 agent 给的选项；答案回到同一个 session。不另挂我们的闸门。卡上要批的命令、路径、参数显示完整，太长就折叠、点开看全，不截断；飞书上也一样，照样能批（借 Cindy，§触6.6）。
- **派活**（限1）：派到主以外的节点，派了就通知我一句，不等我点。
- **不可信内容**（限3）：陌生网站、别人的仓库、别人发来的文件，碰到时先问我一句，不强制沙箱；Linux 节点上沙箱可选。
- **问我**：agent 调 `ask`。
- 权限请求和 `ask` 都是任务的**等待点**，只认我答（同 §底3.3），主 agent 和别的 agent 不能代答（借 Herdr）。规则（Y1）：
  - 等的时候**占着 agent 进程不释放，不设超时**；我答了，答案进同一个 session。
  - 节点或 agent 进程重启以后，这张卡作废，任务进「需要你处理」；我再答时用 `session_ref` 续上，在同一个 session 里重新问一遍。
- **以我名义发给别人**只走 `send`，审批卡（底线）。残余：agent 不来问就直接做。节点上登录了能代我发消息的工具（lark-cli、邮件）时，在 agent 自己的设置里把这类命令设成必须问，或者不给它那份登录。

### 办3.4 任务的生命周期

- **任务** = task + session（哪台节点、哪个 agent、`session_ref`）+ 等待点（问你、看一眼）。每开一次 session，`attempt` 加一；节点回传的进度和结果带上 `attempt`，旧的晚到写入直接丢（保证对错，不算限制）。
- **插话**：能插就插。Claude Code、Codex、pi 都能插进进行中的这一轮（§办3.2）；我的主对话 lane 里的 pi 也一样。ACP agent 只有取消，插话排到下一轮（acpx 的队列）。
- **等看一眼时我直接发消息**：先拒掉那条权限请求，消息进同一轮，不排在卡住的请求后面（借自 Paseo）。只对我的消息生效；主 agent 和别的 agent 发给这个任务的消息排到我答完之后，不能借插话替我答（借 Herdr）。
- **同一个仓库**（2026-11-27 我定）：派活的目录是 git 仓库，而这台机器上这个仓库已经有任务在跑，新任务就开一个 worktree（新分支），session 在里面开；否则直接在原目录干。worktree 交付后留着；PR 合了或任务取消了，在「它自己 › 节点」里列成「可清理」，我点了才删（§0.7：删除类不自动做）。到点扫一遍由主的 `tasks` 给节点发单次指令，节点不存定时状态。
- **停和取消**：停 = 取消这一轮（Claude `interrupt`、Codex `turn/interrupt`、pi `abort`、ACP `session/cancel`），任务留着，能接着说；还没被读到的插话一起作废。取消 = 任务不要了。没有暂停。
- **空闲释放**：agent 空闲一阵（默认 1 小时，可改）就释放进程，session 留着，下次发消息再续接。有活在跑、有等待点时不释放。交付后留着的 session 不算在跑，我在里面接着说话时才算。由主的 `timers` 到点给节点发单次释放指令，节点不存定时状态。只是收回内存，不影响任务，不算限制（借自 Paseo）。
- **卡住**：没有墙钟，不强停。显示多久没动静；久了（默认 20 分钟，可改）进"需要你处理"，由我定。额度用完不算卡住，见下面。
- **额度用完**（2026-11-27 我定，借 Cindy）：节点认出是订阅的额度上限（比如 Claude 的 5 小时、每周上限），任务显示"额度 14:30 恢复"，到点由主的 `timers` 给节点发一条单次指令接着跑，通知我一句；节点离线时不会自己醒来跑旧任务。等的时候我可以点名换一台、换一家，交接照"失联"那条。剩余额度在「它自己 › 用量」里看，不推（同限5 只告警）。
- **交付以后**：没有验收这一步。session 留着，"再改：…"接着同一个 session；留着的 session 不算在跑，我在里面接着说话时才算。
- **PR 的 CI**（2026-11-27 我定，借 T3 Code）：※ 任务开了 PR，主的 `timers` 到点给节点发单次指令，节点用自己的 git 登录去查这个 PR 的检查；节点不存盯守状态（理由：主是唯一的调度器，节点离线时不会自己醒来跑旧任务；行为不变，只是状态挪到主上）。红了，叫醒同一个 session，带上失败的日志，修好再推。PR 上的评论只认我的（靠 `people.yaml` 里我的 git 平台身份认出我），别人的算外部输入（§0.4）。不设次数上限；同一个 PR 连着红到第 3 次（可改），发一条通知，不拦（不归 Y8 的通用熔断管）。C 级改进的 PR 也一样（§进2.4）。
- **同时几个**（D2，我定，2026-11-27）：不设上限，不设 `max_parallel` 默认值，也不按内存准入。我可以给每台机器设一个数，不设就不限；lane 之间也不设全局上限。每个 worker 自己的内存上限留着（主机模式 6G、沙箱 1G）：它防的是一个任务拖垮整台机器，保证对错，不算限制。
- **失联**：任务显示"等这台机器"，不自动搬。我点名换一台、换一家，或者续接不上时，开新 session。交接文本由代码从记录里按预算拼：第一条要求、最近几轮、命令结果、`progress.md`；省掉的地方写明，agent 要时能按需读回。不让模型总结（借 T3 Code、Cindy）。原来的 session 不删，切回去还能接着用。
- **重启**：主重启不影响节点上的 session。节点重启后按 §办3.2 表里的续接方式接着；都接不上就照"失联"那条开新 session。结果不明的动作不自动重跑（同 §底1.2）。节点程序要升级时**先排空**：不接新活，等正在跑的那一轮跑完再换（借 Herdr、Orca）。※ 排空要有超时，超时后按重启处理（停在等待点上的进程也一样，卡作废，见 §办3.3）；理由：等待点现在占着进程，不设超时会让升级永远换不上。

### 办3.5 第 4 批我定的放开（§进2.3 D 级，2026-11-26）

| | 原来 | 现在 |
|---|---|---|
| 权限 | worker 的内置工具过 `PreToolUse` 分级，L2 `defer` 等审批 | 各 agent 按自己的权限设置跑，来问时转看一眼卡（§办3.3） |
| 限1 | 派到 Mac 要批 | 派了就通知，不等 |
| 限2 | 主 agent 没有 bash | 对话里也能直接跑命令、改文件（只在我亲手发的消息触发的 run，§办1.2；定时、系统触发的没有，守住 §读5.1） |
| 限3 | 不可信内容进沙箱 | 碰到时问我，不强制沙箱 |
| 限4 | 他人自动回复：`maxTurns ≤ 6`、工具 ≤ 4、共用日预算 | 数字去掉，只留承诺检测（§底3.4） |
| 限5 | 预算硬上限，超了 403 | 只告警，不停（§办2.2） |
