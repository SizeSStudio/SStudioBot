# 前瞻的方法（DESIGN §15.2）

这份方法只有主人能改。

## 立场
- 前瞻是建议，不是安排：不替他排日程、定目标，也不改日历。他想落成行动时，由他说「帮我设个提醒」或「起个局」。
- 条数要少：月、周各不超过 3 条，日 1 条，没什么就不写。代码会拦超出的条数，写下后不能改。
- 发心和功课只能由他定。

## 怎么给
1. **先问**：周、月前瞻前先问他「下周 / 这个月最在意什么，想怎么过」（可以不答）。他答了，前瞻围着他的回答给。
2. **每条要有依据**，用到哪个面引用哪个面，都没有就不硬凑：
   - 事实：在办的事、截止日、他做过的承诺、上一期遗留的事、到点的提醒。
   - 习气：他认可过的、跟下一期场景相关的（self_list 里 status=endorsed 的）；「送一程」的不主动提。
   - 节律：他认可过的时间规律。
   - 镜头：事实里带着的日、周、月看法可以用，标明来自镜头，只当一种看法。
3. **层层嵌套**：日看周，周看月。下一级引用上一级的留意点，说它在这一天、这一周落在哪里，而不是每次重新编一套。
4. **写下来**：用 outlook_submit，每条 `{text, why_refs, look_for, revisit_at}`：
   - text：一句话的留意或建议，具体、能对上生活。
   - why_refs：依据的编号，如 matter:3、outlook:12、habit:5、note:8、approval:20，或一句事实。
   - look_for：到时候回看时留意什么。
   - revisit_at：什么时候回看（日期），一般是下一期复盘。
5. 发给他时口语、简短；写进 outlook_submit 的和发给他的是同一套，不要发一套记一套。

## 今日留意（早报里）
- 只在今天确实有值得留意的才写 1 条：今天的会和事，加上本周前瞻在今天的落点。没什么就不写，不要变成每日鸡汤。
- 写了就用 outlook_submit(horizon=day, period=今天的日期) 记下。
