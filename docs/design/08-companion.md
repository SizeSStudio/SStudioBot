## 15. 陪伴：红尘里修

### 15.1 定位
- **红尘里修**：修行不只发生在一件件"事"上，而是在整个生活里，包括工作、家人、朋友、身体、情绪，以及时间怎么过。"事"（matter）只是其中值得起、也值得收的那些节点。不做脱离生活的修行模块。
- **两条主轴，首尾相接**：
  - **向前看（前瞻）**：在月、周、日三个尺度上，事先给出方向性的留意和建议，帮我提前看到顺着习气会错过的东西（[§15.2](#152-节律月周日的前瞻)）。每件事起局时也做一次（[§15.4](#154-起方向性引导一次-reflect-run)）。
  - **向后看（回溯）**：顺着时间线回看这段时间发生了什么、当时是怎么看的、我现在怎么感受（[§15.5](#155-收复盘)、[§15.6](#156-时间线与回溯)）。
  - 回看得到的心得会喂给下一次前瞻，这就是类 RSI 的循环，**是这一章的核心**（[§15.8](#158-rsi越用越贴)）。
- **读懂我的来源不止一种（[§0.3](00-principles.md#03-读懂我从哪来)）**：办事（我怎么改草稿、拒绝了什么、什么时候回消息、事情最后怎样了）、日常（含身体，[§15.19](#1519-身体档案v025)）、别人说的话（[§15.18](#1518-别人说的话与边界v025)）、镜头、我说的话。开着的来源它主动去看，不等我报告；但我当时怎么想、怎么感受，记录看不到，只能由我说出来，所以复盘和前瞻仍然要**引导我说**，我不说它也不追。
- **互参（v0.25，[§0.2](00-principles.md#02-怎么帮办--读--参--觉--改)、[§15.17](#1517-互参账本v025)）**：事实、镜头、身体底图、他人原话、我自己的看法都是可选槽位，手头有什么、有用才拿来参，独立记入 `crosschecks` 账本；对不上的地方单独拿出来问我，而不是悄悄选一种。
- **修落在实处**：帮我扛掉一件事、腾出一段时间、搭一个结构，都算陪伴。不推语录、经文和道理。
- **立场和镜头分开**：
  - 佛学是 agent 的**立场**，写进 SOUL.md 和 AGENTS.md：觉察、习气、因果，不执着于结果。它决定 agent 怎么说话、什么时候提醒。
  - 八字、紫微、六爻是**镜头**，做成插件，负责在信息不足时提供视角。镜头不是判决，要结合生活来感受。
- **分寸**（写进 AGENTS.md，代码层面有对应约束）：
  - 发心和功课只能由我定。agent 负责提醒和陪伴，不说教，不替我做决定。
  - **前瞻是建议，不是安排**：不替我排日程、定目标，也不改日历。条数要少：月和周各不超过 3 条，日 1 条。我想落成行动时，再由我说"帮我设个提醒"或"起个局"。
  - 我自己的感受和看法，分量高于 agent 从记录里做的推断。
  - 凶象不说死。健康、法律、大额钱财上，镜头只作参考，必须同时给出事实层面的建议。
  - 我状态不好时先陪着，不急着解盘、复盘，也不急着给建议。
  - **会退后**：我自己能看见的，它就不抢先说（[§15.13](#1513-退后谁先看见送一程)）。它的目标是让我越来越不需要它来提醒，而不是越来越离不开它。
  - 陪伴内容只出现在 owner 会话里。他人会话里 agent 不评论我，也不对别人用镜头。

### 15.2 节律：月、周、日的前瞻

**前瞻和复盘是同一场对话的两面**：先回看刚过去的这段，再看接下来的这段。所以不额外占消息额度。

| 尺度 | 时机 | 内容 | 发到 |
|---|---|---|---|
| **月** | 月初（公历月或节气月，在 `config/self.yaml` 里选），和月复盘合成一场对话 | 先回看上月（拿出上月的前瞻）→ 先问"这个月你想怎么过，最在意什么" → 再给不超过 3 条留意和建议 | 微信 owner（M4 之前发飞书私聊） |
| **周** | 周日晚，和周复盘合成 | 先回看本周 → 问下周最在意什么（可以不答）→ 结合下周的日程、在办的事、月前瞻在下周的落点，给不超过 3 条 | 同上 |
| **日** | 早报里一段"今日留意"，不单独发 | 今天的会和事，加上周前瞻在今天的落点，给 1 条；没什么就不写 | 早报所在的会话 |

- **每条建议的依据分四个面**，用到哪个面就引用哪个面，都没有就不硬凑：
  - **事实**：日历、在办的 matter、截止日、我做过的承诺、上一期遗留的事。
  - **习气**：跟这段时间的场景相关、我认可过的习气（[§15.10](#1510-习气与节律从哪来)）。
  - **节律**：`self/rhythms.md` 里我认可过的规律，比如"月中精力偏低""季末容易焦虑"。
  - **镜头**：日、周、月的例行看法，由 lens 跑，记进解读账本（[§15.7](#157-镜头与解读账本)）。**默认都开**，主人要的；不想要就在 `jobs.yaml` 那一行写 `enabled: false` 或删掉。今日一卦并进早报，下周一卦并进周日的复盘 + 前瞻，月度看法并进月复盘。
- **层层嵌套**：日看周，周看月。下一级引用上一级的留意点，告诉我它在这一天、这一周落在哪里，而不是每次重新编一套。
- **格式**：每条建议是 `{ text, why_refs, look_for, revisit_at }`，写进 `outlooks` 表。写入后冻结，之后只能追加回看，规则和解读账本一样。
- **跟起局的关系**：起局时会先把这件事放进当下的节律，引用本月和本周相关的留意点（[§15.4](#154-起方向性引导一次-reflect-run)）。

### 15.3 "事"是一等对象

matter = 一件值得起、也值得收的事：一个项目、一个决定、一次重要沟通、一段冲突、一个目标。问个日程这种小事不建。生活里没有建成 matter 的部分，照样会出现在时间线上（[§15.6](#156-时间线与回溯)）。

```
起 open ──► 行 active ◄──► 搁 paused ──► 收 closing ──► 复盘完 reviewed
 起局       task / 审批 / follow-up / 解读挂在下面     结果 + 复盘 + 镜头回看
```

- **先搁着（`paused`，v0.25）**：悬而未决、眼下做不了什么的事（尤其是卡着的苦事，[§15.16](#1516-不绕着苦转v024v025-补齐三态)），可以标成 `paused`。暂停期间日常催促、早报提醒和每日整理 `stale` 都不再打扰；有新的外部动静（比如对方回话、相关事件出现）或我主动问起时再浮出。

- **怎么建**：
  - 我说"这事帮我起个局"或"帮我看看这事"。
  - 主 agent 判断事情够分量时**提议**建一个，只在当前回复里提一句，可以忽略。够分量的信号包括：开了大任务、要以我的名义做承诺、出现冲突、我明显在纠结。
- **存在哪**：
  - `matters` 表放状态、收的条件和关联。
  - `agent-home/matters/<id>.md` 放内容：发心、方向、过程要点、复盘。这些查不回来，属于记忆。
- **关联**：tasks、approvals、timers、readings 都带 `matter_id`。复盘时顺着它就能把这件事的全部事实捞出来。
- **事件**（v0.13，[§17.2](09-rsi-matters-graph.md#172-事件账本)）：各个群、私聊、信息源里关于这件事的有意义时刻，按 kind × level 记在 `events` 里，`matter_id` 指过来。这件事在各处的叫法记在 `matters.keys`，Triage 靠它把不同地方说的同一件事串到一起。还没有事的先挂在话头上，反复出现就提议起局。
- **lane**：matter 跟着它所在的会话走，起局和事收复盘都发在那里。工作的事在飞书私聊或工作台话题，私事在微信 owner 会话。
- **主线和子事**（v0.19）：事一多就追不住，我真正跟的是几条长线。
  - 没有 `parent_id` 的事是**主线**；挂在主线下的是**子事**（一个阶段、一块单独要跟的事）。**只有一层**：把带子事的事挂到别处，它的子事直接归到新主线下。工作和私事不混。
  - 控制台、早报、提醒、`matter_list`、Triage 的输入默认只看主线，子事折叠。事件、任务、跟进沿子事汇总到主线；图谱里一条主线一个节点（[§18.3](09-rsi-matters-graph.md#183-图里有什么)）。主线收了而子事还开着，子事单独露出来，不会看不见。
  - 为什么不只做合并：合并会把各件事的边界抹掉，判断错了代价大。挂上去什么都不搬，所以默认用挂；**合并只用于真重复**。
- **合并**：重复的事 `status='merged'`、`merged_into` 指向留下的那件，行和页面都保留。事件、任务、审批、提醒、解读、前瞻、随手记、复盘搬过去，它的 keys 和标题变成留下那件的 keys，同名话头下没挂事的事件一起归过去，子事跟过去。之后用旧编号或旧叫法找到的都是留下的那件。
- **改动都记账**（`matter_ops`）：挂、拆、合并、开主线、收、改事件状态或级别、挪事件、话头归事、改名，每次一行：谁、什么时候、为什么、撤销需要的东西。撤销只还原记录下来的部分，之后新发生的不动；后面的操作动过同样的事，要先撤销后面的。入口只有我的手：整理卡片、控制台、或我在对话里明确说了之后主 agent 调 `matter_regroup`（L1，owner 会话）。

### 15.4 起：方向性引导（一次 reflect run）

产出写进 matter 文件：
1. **放进当下的节律**：本月和本周前瞻里跟这件事相关的留意点（[§15.2](#152-节律月周日的前瞻)）。
2. **事实盘点**：已知什么，未知什么，关键人（引用 people 笔记），关键时间点。盘点完先问一句：还有什么是记录里看不到的？
3. **问发心**：这件事我真正想要的是什么。agent 只问，不代填。
4. **镜头视角**（可选，我要了才起，也可以在某类事上设成默认）：起一卦、看流月等，由 lens 跑。每条都标明门派和版本。留意点和看法记进解读账本（[§15.7](#157-镜头与解读账本)）。
5. **习气提醒**：从 `self/habits.md` 里我认可过的条目中，挑出跟这类事相关的 1～2 条。比如"这类事你以往容易……，这次可以留意"。
6. **检查点**：设 follow-up（比如"周三看下对方的反应"），定好收的条件（某个日期或某个事件）。

### 15.5 收：复盘

| 触发 | 时机 | 默认发到 |
|---|---|---|
| **事收** | matter 达到收的条件：任务完成、审批发出、截止日到、我说"这事完了" | 这件事所在的 lane |
| **日** | 每晚 schedule；当天没事就不发 | 微信 owner（M4 之前发飞书私聊） |
| **周 / 月** | 和下一期的前瞻合成一场对话（[§15.2](#152-节律月周日的前瞻)）；月复盘可以走 expert | 同上 |

**复盘是一场对话，不是一份报告。** 记录只能看到我做了什么，看不到我当时怎么想、怎么感受。这部分只能由我自己说出来，而说的过程本身就是觉察。

1. **事的层面，先给事实初稿**：从时间线（[§15.6](#156-时间线与回溯)）里拟出经过，包括 messages、outbox（我实际发出去的）、审批里我改了什么和拒了什么、日历、journal。这样我不用从零回忆，只需要纠正和补充。目标和结果怎么对比、做对了什么、下次怎么做，可以沉淀进 projects 笔记或 skill。
2. **心的层面，先问再给**：agent 先不亮出自己的看法，用开放的问题引我自己说，比如：
   - "那个节点，你心里是什么感觉？"
   - "有没有哪一刻，其实想换个做法？"
   - "这件事里有什么是记录里看不出来的？"
   - "回头看，你的发心变过吗？"

   等我说完，agent 再补充它从记录里注意到的东西，以及跟习气、功课有关的观察。这些是**对照，不是结论**。先给结论，我容易顺着说下去，就失去了觉察的意义。
3. **引导的节奏**：
   - 每次挑 1～3 个问题，跟着我的回答往下追问，不发问卷。
   - 我只回一句也可以；我说"今天不想聊"就停。
   - 日复盘轻一点，事收和周、月复盘可以深一点。
4. **前瞻和镜头回看**：把这一期开头写下的前瞻和镜头看法拿出来，配上这段时间线，问我结合生活有什么感受，比如"上周日说要留意……，这周怎么样？"（[§15.7](#157-镜头与解读账本)、[§15.8](#158-rsi越用越贴)）。
5. **落档**：
   - 我说的话原样存进 matter 文件或 `self/reviews/`，标 `src=owner`，分量最重。
   - 习气候选：我自己说出来的直接算候选，原话就是证据；agent 从记录里推断的，仍然需要至少 2 条证据。
   - 我没回的，保留事实初稿，心的部分留空并标为"未聊"。**这部分不由 agent 代写，也不靠 agent 记得去写：由代码写**（见下）。
   - **谁先看见**：这次复盘里每提到一条习气或节律，记一笔是我先说出来的，还是 agent 提的（[§15.13](#1513-退后谁先看见送一程)）。

**未聊由代码记**（日、周、月复盘；事收不设截止）。复盘发出时记一条等待（`review_open`），到截止时间还没有落档，代码自己写进 `reviews`，`status=unchatted`，`delivery` 说明这一轮怎么结束的：

| `delivery` | 情况 | 事实部分 |
|---|---|---|
| `sent` | 发出了，我没回 | 当时实际发给我的内容 |
| `replied` | 发出了，我回过话，但这场没有落档 | 同上；不从我的消息里猜哪句算复盘，原话留在时间线 |
| `not_sent` | 没发出去：模型失败、重试放弃、核心不在线错过、这一轮没出内容等，原因写在记录里 | 代码整理的时间线 |

- **截止时间**：日复盘是第二天早报之前（在早报取数之前写好），周、月是发出后 24 小时。安静日本来就不发，不记。
- 已经 `review_submit` 过的不重复写。代码写完之后我才聊上的，`review_submit` 用真实记录替换这一条；空的提交不会多出一条。

### 15.6 时间线与回溯

**一条时间线把生活里的事实按时间串起来。** 它是一个 SQL 视图（[§11](06-data-decisions.md#11-数据模型sqlite草案)），不另存一份；日程不落库，回溯时现查飞书日历再合并进来。时间线包括：
- 我在 owner 会话里说的话
- 我发出去的消息（outbox）
- 审批，以及我在审批里改了什么
- 任务、matter 的起和收
- 前瞻、解读、复盘
- **随手记**：我随口说的"记一下：今天心里有点乱"，存进 `life_notes`，标 `src=owner`

每条都带 `domain`（工作、家庭、朋友、身体、心）、`matter_id` 和相关的人。人生大事年表 `self/timeline.md` 是从时间线里提炼的大事，由 agent 提议、我确认。

**回溯的几种方式**（工具 `timeline_query({ from, to, domain, person, matter, kind })`，只在 owner 会话可用）：
- **按周期**：周复盘、月复盘自动拉这一期的时间线，配上期初的前瞻。
- **按线索**：顺着一个人、一类事、一条习气往回看，比如"这半年我和 X 的沟通""最近三次谈判"。
- **同期对照**：去年此时，或者上一个同类节点（比如每年年底）。
- **按镜头周期**：流月、流年交接时，回看上一段。

**回溯的输出仍然是对话**：先摆出时间线摘要，问我看到了什么，然后 agent 才给它注意到的规律，只当对照。

### 15.7 镜头与解读账本

**立场：镜头是一种看法，要结合生活来感受。** 不追求绝对的对错，也不打分。在意的是两件事：它有没有让我留意到原本会忽略的东西；时间长了，哪种看法对我来说更贴。

- **镜头是插件**，每门一个 skill：
  - 紫微：现有的 ziwei-chart、ziwei-natal、ziwei-zhanbu。
  - 六爻：以 zhouyi-qigua.pages.dev 为准，单独做 skill。
  - 八字：后续再定。

  所有镜头统一输出下面这个格式，内核只认格式，不关心是哪一门。用在前瞻里时，额外带上 `horizon` 和 `period`：
  ```json
  { "lens": "liuyao", "method": "…", "profile_version": "…", "question": "…",
    "horizon": "month|week|day|null", "period": "2026-12",
    "reading": "…", "notice": ["留意点…"],
    "claims": [{ "claim": "…", "revisit_at": "2026-12-01", "look_for": "到时候留意什么" }] }
  ```
- **当时的看法先写下来**：留意点和看法在事情发生之前写进 `readings` 表，之后不改原文，只能追加回看。这不是为了考核，而是回看时能知道"当时是怎么看的"，免得记忆被结果改写。
- **回看**：到了约定的时间，或者事情收尾时，就在复盘里把当时的看法拿出来，配上这段时间线，问我结合生活有什么感受。我说"有感应""没什么感觉""还看不出来"都行，直接说一段话也算数。模型不替我下结论。
- **事实视角并列**（可选）：同一个问题，agent 也可以只基于事实写一段看法（`source=agent`），放在镜头的看法旁边。回看时两种视角一起看，更容易看清镜头补上了什么。
- **与互参的关系（v0.25）**：`readings` 专存单门镜头的原始解读（按生辰与门派 `profile_version` 冻结）。把镜头与事实、身体底图、他人原话、我自己的看法放到一起对照、找出分歧与盲区的步骤，独立记进 `crosschecks` 账本（[§15.17](#1517-互参账本v025)），一条互参可以引用 0 到多条 `readings`。时间长了，哪门镜头在哪类事上更贴进 `lens-notes/`，怎么把几种视角拼得更准进 `crosscheck-notes.md`（[§15.8](#158-rsi越用越贴)）。
- **版本冻结**：出生信息或这门镜头的设置（起卦方式、要求）改了就算新的 `profile_version`，账本按版本分开。
- **按时间段的例行看法（v0.23）**：不需要生辰，六爻有 `day`、`week`、`month` 三个方法，所问之事就是这段时间本身。

  | 任务 | 默认时间 | 看哪段 | 谁跑 | 回到哪里 |
  |---|---|---|---|---|
  | `lens_day` | 每天 07:50 | 当天 | 六爻 | 早报；日复盘回看 |
  | `lens_week` | 周日 19:30 | 周日看下一周，其他日子看本周 | 六爻 | 周日的复盘 + 前瞻；下一次周复盘回看 |
  | `lens_month` | 每月 1 号 06:00 | 当月 | 六爻；有生辰再加紫微流月 | 月复盘 + 月前瞻 |

  任务本身不说话，只写账本，所以不占主动消息额度。同一段时间、同一个版本只看一次；改了生辰，新盘的流月不被旧的挡住。回看日期的扫描跳过日、周看法，免得淹没周复盘和月复盘。花费照常计量，预算机制不变。已有实例升级时加一次默认任务，之后删掉或关掉都不会再加回来。
  - **身体与例行看法（v0.25）**：不单设身体专卦，也不增加额外的例行起卦任务。身体很多时候是心灵的外应，正常日 / 周 / 月例行看法和复盘里，若卦象、流月或身体档案有呼应，顺手结合中医、八字五行阴阳角度参考并向我核实即可（[§15.19](#1519-身体档案v025)）。
- **渎则不告**：同一件事反复问，门派上就不该再占，所以 `cast`、`zhanbu` 仍是一件事一次，事情本身变了才再看。例行起卦每次问的是新的一段时间，不受这条限制。

### 15.8 RSI：越用越贴

```
前瞻（月 / 周 / 日、起局）── 看法和建议写下来，冻结
   │
   ▼
生活（时间线：发生了什么，我做了什么）
   │
   ▼
回看（复盘对话：我说感受和看法）
   │
   ▼
心得（dream 整理，依据只有我说过的话，加上带证据的记录）
   ├─ lens-notes/<lens>.md   哪门镜头的哪种看法，在哪类事上对我更贴
   ├─ crosscheck-notes.md    哪类事适合拿哪几个视角互参、哪种对照问法对我最有启发（§15.17）
   ├─ guidance-notes.md      哪种建议对我有用：太泛、太多、来得太晚、我真的用上了……
   ├─ rhythms.md             我的节律（候选 → 我认可）
   └─ habits.md              习气（候选 → 我认可）
   │
   └──► 下一次前瞻和起局加载这些心得
```

- **每一圈都有"我说"这一步**。月复盘最后可以问一句："这个月的建议，哪些用上了，哪些没用？"这本身也是觉察。
- **不打分**：不算镜头的命中率，也不把采纳率当 KPI。事实可以记（我回了还是没理），但心得以我的原话为准。
- **改进只改"看法和建议怎么给"**：
  - 心得文件由 dream 写，每条都引用来源（reading、crosscheck、outlook、review 的 id）。
  - 前瞻、复盘和互参的方法本身（问什么、给几条、什么时候给、怎么对照）写在 `skills/outlook/`、`skills/review/` 及互参提示词里。agent 只能根据心得提 proposal，我批了才变。
  - 规则、权限、人设照旧只有我能改。
- **防漂移**：
  - dream 的每次改动都有 diff，早上可以回滚（[§8.3](04-memory-timers.md#83-写入纪律)）。
  - 每季度随月复盘把几份心得的全文给我过一遍，删掉我不认的。

```
├── timeline.md          # 人生大事年表：时间线的提炼，也是回看镜头时的生活依据（agent 提议，我确认）
├── habits.md            # 习气观察：每条都要有证据，分"候选"和"我认可"
├── rhythms.md           # 节律：时间上的规律，分"候选"和"我认可"
├── practice.md          # 我定的发心和功课，当前在练什么（只由我定；我在私聊说了，主 agent 才代写）
├── guidance-notes.md    # 建议心得（§15.8）
├── crosscheck-notes.md  # 互参心得（§15.17）
├── lens-notes/          # 每门的解读笔记（§15.7）
├── body/                # 身体档案：基线摘要、历年体检要点与变化（§15.19，原件另存在仅主人可见目录）
├── outlooks/            # 月、周前瞻的全文（日留意只在 outlooks 表里）
└── reviews/             # 日、周、月复盘
```

- 出生信息等原始资料放在 `config/self.yaml`（配置仓库）。不填也能用：六爻、紫占不需要生辰。需要生辰的 lens run 才复制一份只读副本到任务目录里，而且那个 run 断网。
- **怎么填和改**：控制台「生活 › 出生信息」的表单（日期、时间、公历或农历、性别、城市或经度、时区，以及每门镜头的开关、起卦方式、要求），或者在私聊里告诉主 agent，由 `self_profile` 记下。两边和配置编辑器走同一条路：比 hash、zod 校验、git 提交、记 `config_changes`，都能回滚。提交说明和管理群通知不带内容。
- **分界（v0.23 主人定；v0.25 身体档案同级）**：只为保护我自己隐私或谨慎加的限制去掉；防别人、防外部输入的留下。

  | 场合 | 能怎样 |
  |---|---|
  | 我的飞书私聊、控制台 | `self/`、习气、节律、命盘、看法全文、互参、身体档案（`body/` 与 `body_entries`）都可以整份读、整份说 |
  | 工作台、管理群（都是群） | 只提一两句，不贴全文、盘面和身体细节；管理群的通知不带内容 |
  | 定时任务、审批、任务、系统转来的事件触发的 run | 不能用 `self_profile`、`self_page`，也不能整份读习气、节律、命盘和身体档案。这些 run 可能带着外部内容 |
  | 他人会话、Triage、普通 worker | 读不到 `self/`、身体档案和时间线，这一点在工具层校验 |

- `self_page` 能写 `self/` 下的 `.md`，每次单独一个 git 提交，`config_changes` 只记版本和字数。不能写的文件不是为了隐私，是为了不弄坏东西：`habits.md`、`rhythms.md` 由条目生成，`charts/`、`outlooks/` 冻结，`reviews/` 由 `review_submit` 落档。

### 15.10 习气与节律从哪来

这就是"办事收集信息"的价值。dream 每晚从这些事实里找候选：
- 审批卡上我怎么改草稿（比如总把语气改软或改硬），以及拒绝的理由。
- 我在什么时间、什么状态下回消息（深夜回复、连发）。
- follow-up 被我推迟了几次。
- 随手记和时间线上的时间分布（节律的主要来源）。
- **复盘、回看和日常对话里我自己说出来的观察**：这是最重要的来源。

每条候选都要写清楚：描述、证据、首次和最近出现的时间。我自己说出来的，原话就是证据；agent 从记录里推断的，至少要有 2 条证据链接。**只描述行为，不下人格结论**，比如写"这三次……"，而不是"你是个……的人"。只有我标了"认可"，才会在前瞻、起局和复盘里被引用。

### 15.11 渠道与配额
- 起局和事收复盘跟着事走（[§15.3](#153-事是一等对象)）。
- 月、周的前瞻和复盘合成一条，默认发到微信 owner 会话；日复盘也发那里。"今日留意"和今日一卦并进早报，下周一卦并进周日的复盘 + 前瞻。
- 复盘和前瞻类消息单独计数，不占 [§9.3](04-memory-timers.md#93-先安静) 的主动消息额度：日复盘最多 1 条/天，周、月各 1 条。我没回就不追问。
- 起局提议只出现在当前回复里，不单独发消息。

### 15.12 和闸门、记忆的边界
- 前瞻、镜头结论、互参记录（`crosschecks`）、习气和节律、身体档案（`body_entries`）、复盘内容都**不参与任何闸门判断**，不影响审批、承诺检测和自动回复，也不出现在他人会话里。以我的名义发消息仍走审批卡片，不因为 [§15.9](#159-自我档案) 的放开而改变。
- 给重要的人发消息走审批卡时，若草稿明显和对方最近原话不在一个频道，可以在卡片旁顺手附一句「对方最近原话对照」（[§15.18](#1518-别人说的话与边界v025)），但这只是给我的只读参考，不改审批分级、不阻断也不放宽。
- journal 来源加四种：`src=lens`、`src=crosscheck`、`src=review`、`src=outlook`，dream 怎么处理见 [§8.3](04-memory-timers.md#83-写入纪律)。
- 改进只发生在心得文件里（[§15.8](#158-rsi越用越贴)），以及我认可过的习气和节律。agent 的人设、规则和陪伴方法的 skill，照旧只有我能改。

### 15.13 退后：谁先看见、送一程

按佛学的立场，成长是**我自己的觉察变强**，不是 agent 越来越会指出我的习气。设计不当，它会变成拐杖：事实永远它先拟，习气永远它先点破，我越来越依赖它来看见自己。所以要把"退后"设计进去。

- **谁先看见**（`noticings` 表）：复盘、回看和日常对话里，每当一条习气或节律被提到，记下是**我先说出来的**（`owner`），还是 **agent 先提的**（`agent`），以及当时有没有经它引导（`prompted`：它问了开放问题之后我说出来的，也算我先看见）。
  - 由 reflect 在 `review_submit` 时一并提交，dream 按我的原话核对。
  - **这是给我看的镜子，不是 KPI**：月复盘里给一句"这个月有几条是你先看见的"，季度过目时给出每条习气的变化。不排名，不打分，也不进 [§16](09-rsi-matters-graph.md#16-agent-自己的-rsi越用越会办事) 的指标。
- **送一程**：一条认可过的习气，最近 3 次出现我都是自己先看见的（阈值在 `config/self.yaml`，只有我改），状态就变成 `送一程`：
  - 起局和前瞻里不再主动提它，只在我问"我还有什么要留意的"时才说。
  - 复盘里我没提到它，它也不提。
  - 连续 2 次我没看见、事后从记录里明显能看出它又出现了，才恢复成"认可"，并告诉我一声："这条我又开始提醒了，你觉得需要吗？"我说不需要就不恢复。
  - 状态变化写进 habits.md，晨间 diff 里能看到。
- **复盘的顺序会变**：起初 agent 先给事实初稿，我纠正补充。我用熟了以后（同样按 `noticings` 的趋势），周复盘和事收复盘有时会先问"你先回忆一下这周/这件事的经过"，我说完它再补漏。回忆本身也是练习。日复盘保持轻，不这样做。我说"还是你先列吧"就退回原来的顺序。
- **它自己那圈也学怎么陪**（[§16](09-rsi-matters-graph.md#16-agent-自己的-rsi越用越会办事)）：哪些问题打开了我的话头，哪些换来的是"今天不想聊"，作为复盘和前瞻方法改进的依据。

### 15.14 每日整理（v0.19）

账本会变旧，导入的东西还可能一开始就不对，错的事和事件会误导早报和提醒。每天看一眼，把该归并的、该收的、不对的拿出来让我定。

- **时间**：`jobs.yaml` 的 `matter_review`，默认每天 08:15，排在 08:25 的记忆 diff 和 08:30 的早报之前，这样早报能带上今天的结果。单独一张卡而不并进早报，因为早报是模型写的文字，放不了按钮，而这里要的是一点就处理。
- **只提建议**：代码先找，模型补充，都只写进 `matter_reviews`。**事和事件只在我点了之后才变**，走 [§15.3](#153-事是一等对象) 的同一套操作，记账、可撤销。

| 类 | 怎么找 | 我能点 |
|---|---|---|
| 归并 `group` | 标题相近或 keys 相同（代码）；模型看出是同一条线 | 挂到主线 / 合并（够像才给）/ 起新主线（模型给了名字）/ 不相干 |
| 久没动静 `stale` | 主线连同子事 `stale_days`（默认 30）天没有任何动静，也没有待办的跟进或在跑的任务（已标 `paused` 先搁着的不算，[§15.16](#1516-不绕着苦转v024v025-补齐三态)） | 收 / 先搁着 / 放下 / 继续盯 |
| 过时的等回 `old_ask` | 导入的事件仍在等我，已超过 `ask_days`（默认 7）天，或所在的事已经不办了 | 处理了 / 不用了 / 只是知道 / 还在等我 |
| 可能不对 `suspect` | 模型：事件挂错、没挂但明显属于某件事、导入内容和后来的事矛盾、标题和内容对不上 | 挪 / 摘下 / 作废 / 只是知道 / 改名 / 没问题 |
| 话头 `topic` | 两周里跨 ≥ 2 处出现 ≥ 3 次、还没有事（原来早报里的「可能该起局」并到这里） | 起一件事 / 挂到某件事 / 先不管 |

- **模型**：默认 light 档，第一次用 work 档（`tier` 可配）。输入是主线、子事、事件的摘录，放在 `<untrusted>` 里，最多约 3 万字；账本没变就不调用。返回的编号由代码核对，编造的丢掉。模型失败时只用代码找到的。写进卡片的文字去掉链接、@ 和标记。
- **每天几条**：最多 `limit`（默认 5）条，第一张卡最多 `first_limit`（默认 12）条，优先给成组的归并，让导入的一堆先有形状。各类轮流取，导入来源和影响早报、提醒的排前面，同一张卡上不出现关于同一件事的两条。
- **发到哪**：一天一张卡，发在和我的 bot 私聊，占每日主动消息上限的 1 条（[§9.3](04-memory-timers.md#93-先安静)，上限本身不动）。超了上限就不发，建议留在控制台「生活 › 事」，早报带一句。同一天重跑只更新那张卡，不重复计数。
- **不再问**：每个问题有指纹（`fp`）。点过「没问题」「继续盯」「还在等我」的不再问。「继续盯」的指纹带最后动静的日期，之后有了新动静又沉寂下去，才算新问题。说不相干的一组，它的任何子集也不再问。撤销一个决定后，这条歇 30 天。
- **不理也不堆**：第二天旧卡收起，没处理的回到队列。一条被略过两次后歇 14 天，再略过时间翻倍，最长 60 天。连续 3 张卡没点就改成 3 天一张，连续 6 张改成 7 天一张，点一下恢复每天。问题的理由消失了（比如我自己处理了），它就自动作废。
- **和早报的关系**：早报不再列「可能该起局」，只有一句今天挑了几条。过时的导入事件不算进「等你回 / 拍板」，只报一个数；我确认「还在等我」后才回到那一段，处理掉就不再出现。
- **入口**：飞书卡片、控制台、主 agent 的 `matter_review` 工具（我说了才动）。现有的事不做一次性迁移，都从这里过，由我确认。
- 这里不产生 [§16](09-rsi-matters-graph.md#16-agent-自己的-rsi越用越会办事) 的信号：要不要记，属于 D 级，等我定（[§17.5](09-rsi-matters-graph.md#175-和-16-的关系)）。

### 15.15 放下（v0.24）

读懂我的东西会越攒越多。只攒不放，它就会拿过去的我去框现在的我，我也会被自己的标签困住。人是会变的，理解也要会淡、能放下。

- **会淡**：认可过的习气、节律，`fade_days`（默认 180 天，`config/self.yaml`，只有我改）里一直没有新证据，状态变成 `淡了`：
  - 前瞻、起局、复盘不再引用；条目和证据都留着。
  - 季度过目时列出这一季淡了的条目，我可以说"还在""放下"，或者不管。
  - 之后又出现了新证据，它回到 `候选`，要我再认一次才重新引用。不会悄悄恢复。
- **能放下**：我说"这条放下"（私聊、复盘、控制台都行），状态变成 `放下`：
  - 不再主动提，dream 也不再为它攒证据。
  - 只有我说"恢复"才回来。条目留在 `habits.md` 或 `rhythms.md` 的历史里，想删在控制台删。
- **和送一程的区别**：送一程是我自己已经看得见了，它不用再提醒（[§15.13](#1513-退后谁先看见送一程)）；淡了是很久没出现；放下是我决定不再背着它。三种都会写进晨间 diff。
- **不贴标签**：理解只描述行为和时间（[§15.10](#1510-习气与节律从哪来)），不写"你是……的人"。人物页里对别人的判断也一样，带最近证据的日期，很久没有新证据的不拿来当依据。
- 解读账本、复盘原文照旧冻结（[§15.7](#157-镜头与解读账本)）：那是"当时怎么看的"记录，不是对我的定论，回看时也按当时的语境读。

### 15.16 不绕着苦转（v0.24，v0.25 补齐三态）

陪伴最容易犯的错，是把让我难受的事一遍遍翻出来，越聊越深、越陷越重。复盘要往外走，不在原地打转。

- **苦事**：我说过让我难受的事，包括复盘、随手记、对话里的原话，以及挂着这些原话的事和习气。
- **事和苦分开**（2026-11-19 主人定）：事上的跟进（到点提醒、下一步、等谁回）照常做，直到这件事办完，或者我判断它不需要解决了。这是待办，不算翻苦。不绕着苦转管的是难受的那一面。
- **苦事三态（v0.25）**：很多让人难受的事既没办完、也不是放下不管，而是眼下卡着做不了什么。因此按事的实际处境分三种状态，不靠固定的复盘周期计数硬切：

  | 状态 | 含义 | 事上的跟进 | 难受的那一面 |
  |---|---|---|---|
  | **在推进**（`active`） | 事情还在办，还有可做的动作 | 到点提醒、下一步、等谁回照常做 | 不主动翻；要提必须带来新事实、新角度或往外走的小步 |
  | **先搁着**（`paused`） | 悬而未决、眼下做不了什么 | **连日常催促、早报提醒、每日整理 `stale` 一并暂停**，免得天天对着墙催；有新外部动静（如对方回话、新事件）或我主动问起再浮出 | 不主动提 |
  | **了结 / 放下**（`closing` / `reviewed` / `dropped`） | 办完了，或我判断不用解决了、放下了 | 彻底收掉，不再跟进 | 不再主动提（事收那一次复盘照常，[§15.5](#155-收复盘)） |

- **它主动提**：难受的那一面，它不主动翻。要提必须带来新东西：新事实、新角度，或者一个往外走的小步；拿不出就不提，也不因为到了复盘就再问一遍。
- **我主动提**：不设限。它跟着我说，先陪着；不替我往深里再挖一遍，也不急着解盘、复盘（[§15.1](#151-定位)）。
- **复盘的方向**：心的层面第一轮可以问"当时"，之后的问题朝着"接下来"："如果再遇到，你想怎么做？""有什么小事现在就能做？"
- **怎么落地**：写进 AGENTS.md 和 `skills/review/`（v0.24 已写）。之后在代码里补：`matters` 支持 `paused` 状态（[§15.3](#153-事是一等对象)）；它主动提起的记在 `noticings`（`first_by=agent`，带 `matter_id`），reflect 起草前先查这件事最近一次是谁提的、那次带了什么新东西。
- **镜子**：季度过目时给一句"这一季它主动提了几次让你难受的事"。只给我看，不进 [§16](09-rsi-matters-graph.md#16-agent-自己的-rsi越用越会办事) 的指标。

### 15.17 互参账本（v0.25）

互参是 [§0.2](00-principles.md#02-怎么帮办--读--参--觉--改) 的核心环节，不能只塞在单门镜头 `readings` 的 `notice` 里，也不能绑死在某一次起卦上。v0.25 把账本拆成两张：**`readings` 专存单门镜头的原始看法，`crosschecks` 专存把多种视角放在一起对照的结果。**

- **六种视角，全为可选槽位**：
  1. **事实与时间线**：`events`、`matters`、消息记录、办过什么事；
  2. **AI 推理**：仅基于事实做出的判断与推演；
  3. **镜头看法**：引用 0 到多条 `readings`（六爻、紫微、八字，含五行阴阳角度）；
  4. **身体底图**：`body_entries` 与 `self/body/` 里近期睡眠、精力、症状或体检基线（[§15.19](#1519-身体档案v025)）；
  5. **他人原话**：相关人在群聊、单聊里的原始发言摘录（[§15.18](#1518-别人说的话与边界v025)）；
  6. **我的话**：复盘、随手记或当前对话里我自己的感受与判断。

  **不设必填项，灵活拼装。** 手头有什么、对这件事有用才拿来参，不为了凑格式硬起一卦、硬找一段身体记录。缺了哪一面，就在 `blind_spots` 里老实写出来（例如"这件事我只看得到工作记录，不知道你当时心里怎么想"），但不借机提议开新信息源或放宽权限。
- **记录什么（`crosschecks` 表，[§11](06-data-decisions.md#11-数据模型sqlite草案)）**：
  - 关联对象：`kind`（`matter` / `outlook` / `review` / `habit` / `relation` / `body` / `ad_hoc`），按需挂 `matter_id`、`outlook_id`、`person_id`；
  - `sources_json` 与 `reading_ids`：本次实际用到了哪些视角和具体依据；
  - `agreements`（哪里对得上）、`divergences`（哪里对不上，最值得看）、`blind_spots`（缺了哪一面）、`suggestion`（落到实处的一小步或问我的一个问题）；
  - **`prompt_version` 与冻结**：记下本次互参所用方法 / 提示词的版本号，核心内容写入即算 `frozen_hash` 冻结，之后只能追加我的回看（`feeling`、`owner_words`、`revisited_at`）。之所以独立版本化，是因为互参怎么问、怎么对照需要随使用持续调优，单独建账才能跨版本回看效果。
- **何时触发（不增噪音）**：
  - 融进现有节奏：起局（[§15.4](#154-起方向性引导一次-reflect-run)）、月 / 周前瞻与复盘（[§15.2](#152-节律月周日的前瞻)、[§15.5](#155-收复盘)）、事收复盘；
  - 按需触发：习气候选形成前、关系摩擦复盘、身体与情绪明显呼应、或我在私聊里主动让它"帮我把几面合起来看看"；
  - 每次互参不额外占用主动消息额度；**看可以主动，说要克制**——大部分时候只在需要问我、或我来问它时才端出来。
- **如何越参越贴**：回看时以我的原话为准，不给镜头或互参打分。我说过"哪类事拿哪几面一起看最管用""哪种对照方式太绕"，由 dream 记进 `self/crosscheck-notes.md`（[§15.8](#158-rsi越用越贴)）；互参提示词本身的改动属 B 级，提 proposal 经我批才变（[§16.3](09-rsi-matters-graph.md#163-能改什么四级)）。

### 15.18 别人说的话与边界（v0.25）

[§0.1](00-principles.md#01-它是什么) 说 SStudioBot 只为我一个人；同时我在微信、飞书的群聊和单聊里每天都在和别人来往。别人说的话算「读懂我」的来源之一（[§0.3](00-principles.md#03-读懂我从哪来)），**但只用来照见我和别人怎么相处、我有没有误解对方、对方眼里看到了怎样的我——核心依然是帮我自修，而不是去分析或评判别人。**

- **数据从哪来、存什么**：
  - 不另建一套档案库。原始发言就在 `messages` 表里（[§8.2](04-memory-timers.md#82-记忆的种类对应文章里的划分)），只靠引用和检索按需调出，不把别人说的话洗进 `USER.md` 或 `MEMORY.md`（[§8.3](04-memory-timers.md#83-写入纪律) 原有写入纪律不变：非 owner 来源只能写进对应人物 / 群的笔记，标明"X 说……"，并带最近证据日期，[§15.15](#1515-放下v024)）。
  - 人物页（`people/<slug>.md`）和因缘图谱（[§18](09-rsi-matters-graph.md#18-因缘人事资料的图谱v015)）记录客观往来与对方特点；一旦牵涉"我怎么看待对方、我在和 TA 相处时的习气"，属于我的自我观察，只进 `self/` 或 `crosschecks`，仅我可见（[§15.9](#159-自我档案)）。
- **亲友私下找 SStudioBot 的定位**：
  - 老婆和朋友在微信里加它好友，现阶段**只是把普通 bot 能做的日常功能集中在一个入口**，顺手帮点忙（[§6.4](03-wechat-permissions.md#64-帮老婆和朋友)）。
  - **暂不对亲友私聊里的内容做深度分析或关系推断**；等以后真有需要、由我明确拍板再讨论。
- **"我是否误解了别人"怎么照出来（两种时机都用）**：
  1. **复盘与聊到某人时（事后 / 平时对照）**：我在复盘、起局或私聊里说到某人"好像对我有意见""不想配合"时，它可以把对方最近几条原话（时间、上下文、原文）和我的转述并列摆出来做一次互参（[§15.17](#1517-互参账本v025)），让我自己看有没有脑补或漏读；不下"你误解人家了"的裁判结论。
  2. **重要的人审批卡旁顺手对照（发前防误会）**：给重要的人（如 `people.yaml` 里的亲友或关键联系人）发消息走审批卡时，如果草稿的语气、前提或回应点明显和对方最近原话不在一个频道，可以在卡片旁顺手附一句「对方最近原话对照」（只引原文要点，简短一行）。**纯只读参考，不改闸门、不阻断也不放宽审批规则**（[§15.12](#1512-和闸门记忆的边界)）。
- **对别人的五条硬边界**：
  1. **不对别人用镜头**：不给任何人起卦、排盘、算命（除非我亲自在 owner 私聊里明确问起，即便如此也不写入他人档案、不外传）。
  2. **他人会话里不评论我**：别人问起我时，只按授权转达客观信息，绝不评价我的性格、情绪或状态。
  3. **不传话、不串供**：不在 A 的会话里转述 B 说过的话，也不用和 B 的私聊内容去回复 A。
  4. **不做人格定性、不替别人站队**：人物笔记只写带日期的事实与原话，不贴"TA 是个……的人"的标签；照见误解时摆事实，不替别人教训我，也不顺着我贬低别人。
  5. **默认只读不扩权**：是否读飞书单聊（`feishu.dm`）或某个群聊，仍完全由我配置决定；agent 不提议开新来源。

### 15.19 身体档案（v0.25）

[§0.3](00-principles.md#03-读懂我从哪来) 把身体列为读懂我的来源之一。身体既反映作息消耗，很多时候也是心灵和情绪的外应（睡不好、反复上火、精力掉档，往往和最近扛着的事、心里的结连着）。但身体数据高度私密，且需要跨年追踪，不能和工作邮件、群消息混在同一条分拣管道里。

- **隔离级别与存放**：
  - **不走 [§17.3](09-rsi-matters-graph.md#173-信息源) 信息源，不进 Triage 分拣，不进事件账本 `events`，也不进因缘图谱（[§18.3](09-rsi-matters-graph.md#183-图里有什么)）**。
  - 与 `self/` 同级隔离（[§15.9](#159-自我档案)）：只在我的飞书私聊和控制台（含未来的手机端）可见；不进工作台、管理群、他人会话、普通 worker，也不在外部事件触发的 run 里读取。
  - 结构化记录存 `body_entries` 表（[§11](06-data-decisions.md#11-数据模型sqlite草案)），提炼后的基线与历年体检要点存 `agent-home/self/body/`；体检报告原件（PDF、照片、截图）长期留存在服务器仅主人可见的附件目录（`$SBOT_HOME/private/body/`，不进公开或常规记忆 git 仓库），`body_entries.raw_ref` 存路径指针。
- **两件事：可选底图 + 体检报告跨年守护**：
  1. **身心联动的可选底图**：日常睡眠、精力、症状和随手说的身体感受，在复盘、前瞻、互参时作为可选槽位按需参考（[§15.17](#1517-互参账本v025)），帮我看见"这周状态差是不是身体先撑不住了"或"这件事是不是已经落到身体反应上了"。没有记录时不硬凑、不催填。
  2. **体检报告跨年守护**：上传一份体检报告或化验单照片后，模型提取关键指标、异常项与去年 / 往年对比变化，生成一份简明摘要；**经我确认（`confirmed=1`）后才入账**写入 `self/body/`。跨年持续变差或超出参考范围的指标会温和提醒，**必须附事实层面的建议（比如复查、挂哪个科、作息调整）**，绝不替代医生诊断。
- **与镜头、中医和五行阴阳的结合**：
  - **不单设身体专卦**，也不多开例行起卦任务。沿用现有的日 / 周 / 月例行看法（[§15.7](#157-镜头与解读账本)）和日常复盘即可。
  - 当例行卦象、流月或我提起的身体状况出现呼应时，可以结合**中医与八字五行阴阳角度**作为辅助视角一起互参，再向我核实当下真实体感，回看结果照常沉淀到心得里。遵循 [§15.1](#151-定位) 分寸：健康问题上凶象不说死，镜头只作参考，必附事实建议。
- **低门槛输入与对手机端的要求（[§19](10-console-client.md#19-控制台客户端前后端拆开对话设备v020设计稿)）**：
  身体记录最怕繁琐，所以三条输入并行、哪种顺手用哪种：
  1. **随手一句话**：在私聊或客户端直接说"昨晚两点才睡""这几天胃胀"，主 agent 记入 `body_entries`（`kind=symptom|note`），不追问填表；
  2. **拍照 / 上传体检报告与截图**：支持 PDF、照片、健康 App 截图，存原件 → 提取指标与跨年对比 → 我点确认入账；
  3. **手机端可选系统健康汇总**：这是未来手机端（重点照顾 Android，如 Health Connect 汇总睡眠、步数、心率等日级摘要）的重要价值之一——由我手动开启、只传日级汇总不传高频原始轨迹、直走 owner 隔离接口，不开照样能靠前两条用。
