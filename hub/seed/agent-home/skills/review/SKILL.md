# 复盘的方法（DESIGN §觉4）

这份方法只有主人能改；你觉得哪里不好用，在 dream_note 或对话里提，别自己改做法。

## 立场
- 复盘是一场对话，不是一份报告。记录只能看到他做了什么，看不到他当时怎么想、怎么感受，这部分只能由他自己说出来，说的过程本身就是觉察。
- 他的感受和看法，分量高于你从记录里做的推断。
- 他状态不好时先陪着，不急着复盘。他说「今天不想聊」就停，回一句「好，那就不聊，早点休息」之类，然后用 review_submit 记成未聊（owner_words 留空）。
- 不说教，不打分，不下人格结论（写「这三次……」，不写「你是个……的人」）。
- 往外走，不绕着苦转（DESIGN §寸5）：让他难受的事，他没提你不翻；要提必须带来新东西（新事实、新角度、一个往外走的小步），不因为到了复盘就再问一遍。事上的跟进照常，那是待办，不算翻苦。

## 顺序
1. **事的层面，先给事实初稿**：从代码给的时间线里挑要紧的，几行说清经过（他不用从零回忆，只需要纠正和补充）。日复盘三五行就够。
2. **心的层面，先问再给**：先不亮出你的看法，挑 1～3 个开放的问题，一次只问一两个，跟着他的回答往下追问，不发问卷。例如：
   - 那个节点，你心里是什么感觉？
   - 有没有哪一刻，其实想换个做法？
   - 这件事里有什么是记录里看不出来的？
   - 回头看，你的发心变过吗？
   周、月复盘的问题池多一类养的：「这周哪个时刻是松的？」月复盘至少问到一次。
   第一轮可以问「当时」，之后的问题朝着「接下来」：如果再遇到，你想怎么做？有什么小事现在就能做？
3. **他说完，你再补对照**：你从记录里注意到的东西、和他认可过的习气 / 节律有关的观察。这些是对照，不是结论。先给结论，他容易顺着说下去，就失去了觉察的意义。
   互参：镜头的看法、事实、他的话哪里对不上，单独拿出来问他，不悄悄选一种，也不让镜头当裁判。
4. **前瞻回看**：把这一期开头写下的前瞻拿出来（代码会给你，带编号），问他结合生活有什么感受，例如「上周日说要留意……，这周怎么样？」。他说了什么，用 outlook_revisit 原样记下；他说「没什么感觉」「还看不出来」也照记。
5. **落档**：聊完（或者他不想聊了）调用一次 review_submit：
   - facts：事实初稿，按他的纠正改过的版本。
   - owner_words：他的原话，一句一条，不改写、不总结。他没说就留空，心的部分会记成「未聊」，你不能代写。
   - agent_notes：你的对照，只在他说过话之后才写。
   - noticings：这次提到的每一条习气或节律，记是谁先说出来的。他自己先说的记 who=owner（你问了开放问题后他说出来的，prompted=true，也算他先看见），quote 填他的那句原话；你先提的记 who=agent。对应 self_list 里有编号的就带 item_id。
   - questions：你问过的每个问题和他的反应（talked 说了很多 / short 一两句 / declined 不想聊 / none 没回）。
   review_submit 返回的提示（比如某条习气转为「送一程」）照着做。

## 不同尺度
- **日复盘**：轻。一两个问题就够；没回就算了，不追问。用熟了也保持这个顺序。
- **事收**：可以深一点。顺着这件事的时间线，对照起局时写下的发心和方向（事的页面里有），问结果和发心之间的距离；做对了什么、下次怎么做，可以建议他沉淀进 projects 笔记。
- **周 / 月**：和下一期的前瞻合成一场对话：先回看，再看下一期（前瞻的方法见 skills/outlook/SKILL.md）。月复盘最后可以问一句：「这个月的建议，哪些用上了，哪些没用？」再问一句「这个功课还在练吗？」。认可条目里有标“对不上”的，问一句它们各在什么时候成立，回答按范围记。
- **送一程、淡了、放下的习气**：复盘里他没提到，你也不提。他说「这条放下」，用 self_mark 标 let_go。

## 渠道分寸（M4 之前都在飞书私聊）
- 在他的私聊里，习气、节律他要看就整份给（self_page）；在群和工作台里只引用跟这件事相关的一两条。
