## 参1 镜头与解读账本

**立场：镜头是一种看法，要结合生活来感受。** 不追求绝对的对错，也不打分。在意的是两件事：它有没有让我留意到原本会忽略的东西；时间长了，哪种看法对我来说更贴。

- **镜头是插件**，每门一个 skill：
  - 紫微：现有的 ziwei-chart、ziwei-natal、ziwei-zhanbu。
  - 六爻：以 zhouyi-qigua.pages.dev 为准，单独做 skill。
  - 八字：后续再定。

  所有镜头统一输出下面这个格式，内核只认格式，不关心是哪一门。用在前瞻里时，额外带上 `horizon` 和 `period`：
  ```json
  { "lens": "liuyao", "method": "…", "profile_version": "…", "question": "…",
    "horizon": "month|week|day|null", "period": "2026-12",
    "reading": "…", "notice": ["留意点…"],
    "claims": [{ "claim": "…", "revisit_at": "2026-12-01", "look_for": "到时候留意什么" }] }
  ```
- **当时的看法先写下来**：留意点和看法在事情发生之前写进 `readings` 表，之后不改原文，只能追加回看。这不是为了考核，而是回看时能知道"当时是怎么看的"，免得记忆被结果改写。
- **回看**：到了约定的时间，或者事情收尾时，就在复盘里把当时的看法拿出来，配上这段时间线，问我结合生活有什么感受。我说"有感应""没什么感觉""还看不出来"都行，直接说一段话也算数。模型不替我下结论。
- **事实视角并列**（可选）：同一个问题，agent 也可以只基于事实写一段看法（`source=agent`），放在镜头的看法旁边。回看时两种视角一起看，更容易看清镜头补上了什么。
- **与互参的关系（v0.25）**：`readings` 专存单门镜头的原始解读（按生辰与门派 `profile_version` 冻结）。把镜头与事实、身体底图、他人原话、我自己的看法放到一起对照、找出分歧与盲区的步骤，独立记进 `crosschecks` 账本（§参2），一条互参可以引用 0 到多条 `readings`。时间长了，哪门镜头在哪类事上更贴进 `lens-notes/`，怎么把几种视角拼得更准进 `crosscheck-notes.md`（§进1）。
- **版本冻结**：出生信息或这门镜头的设置（起卦方式、要求）改了就算新的 `profile_version`，账本按版本分开。
- **按时间段的例行看法（v0.23）**：不需要生辰，六爻有 `day`、`week`、`month` 三个方法，所问之事就是这段时间本身。

  | 任务 | 默认时间 | 看哪段 | 谁跑 | 回到哪里 |
  |---|---|---|---|---|
  | `lens_day` | 每天 07:50 | 当天 | 六爻 | 早报；日复盘回看 |
  | `lens_week` | 周日 19:30 | 周日看下一周，其他日子看本周 | 六爻 | 周日的复盘 + 前瞻；下一次周复盘回看 |
  | `lens_month` | 每月 1 号 06:00 | 当月 | 六爻；有生辰再加紫微流月 | 月复盘 + 月前瞻 |

  任务本身不说话，只写账本，所以不占主动消息额度。同一段时间、同一个版本只看一次；改了生辰，新盘的流月不被旧的挡住。回看日期的扫描跳过日、周看法，免得淹没周复盘和月复盘。花费照常计量，预算机制不变。已有实例升级时加一次默认任务，之后删掉或关掉都不会再加回来。
  - **身体与例行看法（v0.25）**：不单设身体专卦，也不增加额外的例行起卦任务。身体很多时候是心灵的外应，正常日 / 周 / 月例行看法和复盘里，若卦象、流月或身体档案有呼应，顺手结合中医、八字五行阴阳角度参考并向我核实即可（§读5.2）。
- **渎则不告**：同一件事反复问，门派上就不该再占，所以 `cast`、`zhanbu` 仍是一件事一次，事情本身变了才再看。例行起卦每次问的是新的一段时间，不受这条限制。

## 参2 互参账本（v0.25）

互参是 §0.2 的核心环节，不能只塞在单门镜头 `readings` 的 `notice` 里，也不能绑死在某一次起卦上。v0.25 把账本拆成两张：**`readings` 专存单门镜头的原始看法，`crosschecks` 专存把多种视角放在一起对照的结果。**

- **六种视角，全为可选槽位**：
  1. **事实与时间线**：`events`、`matters`、消息记录、办过什么事；
  2. **AI 推理**：仅基于事实做出的判断与推演；
  3. **镜头看法**：引用 0 到多条 `readings`（六爻、紫微、八字，含五行阴阳角度）；
  4. **身体底图**：`body_entries` 与 `self/body/` 里近期睡眠、精力、症状或体检基线（§读5.2）；
  5. **他人原话**：相关人在群聊、单聊里的原始发言摘录（§读6）；
  6. **我的话**：复盘、随手记或当前对话里我自己的感受与判断。

  **不设必填项，灵活拼装。** 手头有什么、对这件事有用才拿来参，不为了凑格式硬起一卦、硬找一段身体记录。缺了哪一面，就在 `blind_spots` 里老实写出来（例如"这件事我只看得到工作记录，不知道你当时心里怎么想"），但不借机提议开新信息源或放宽权限。
- **记录什么（`crosschecks` 表，§底5）**：
  - 关联对象：`kind`（`matter` / `outlook` / `review` / `habit` / `relation` / `body` / `ad_hoc`），按需挂 `matter_id`、`outlook_id`、`person_id`；
  - `sources_json` 与 `reading_ids`：本次实际用到了哪些视角和具体依据；
  - `agreements`（哪里对得上）、`divergences`（哪里对不上，最值得看）、`blind_spots`（缺了哪一面）、`suggestion`（落到实处的一小步或问我的一个问题）；
  - **`prompt_version` 与冻结**：记下本次互参所用方法 / 提示词的版本号，核心内容写入即算 `frozen_hash` 冻结，之后只能追加我的回看（`feeling`、`owner_words`、`revisited_at`）。之所以独立版本化，是因为互参怎么问、怎么对照需要随使用持续调优，单独建账才能跨版本回看效果。
- **何时触发（不增噪音）**：
  - 融进现有节奏：起局（§觉3）、月 / 周前瞻与复盘（§觉2、§觉4）、事收复盘；
  - 按需触发：习气候选形成前、关系摩擦复盘、身体与情绪明显呼应、或我在私聊里主动让它"帮我把几面合起来看看"；
  - 每次互参不额外占用主动消息额度；**看可以主动，说要克制**——大部分时候只在需要问我、或我来问它时才端出来。
- **取信**（v0.26，人物页同样用，§读4.7）：
  - 先分清是哪种不同：同一件事的几份副本、互补的两面、对象不同、时段不同。分得进去的不算矛盾，分不进去的才拿出来问我。
  - 来源多不赢投票；同一份证据被抄进几处只算一次。
  - 新近的只是线索，不自动盖掉旧的；我的更正在我说的范围里作数。
  - 说不清的挂成“有争议：A（出处、日期）对 B（出处、日期）”，有新证据才收，收时写明是哪条。
- **如何越参越贴**：回看时以我的原话为准，不给镜头或互参打分。我说过"哪类事拿哪几面一起看最管用""哪种对照方式太绕"，由 dream 记进 `self/crosscheck-notes.md`（§进1）；互参提示词本身的改动属 B 级，提 proposal 经我批才变（§进2.3）。

## 参3 Reflect 与 Lens（陪伴相关的两个角色，§参、§觉）
- **reflect**（chat 档；月前瞻、月复盘和大事起局可以走 expert）：负责前瞻、起局、复盘和回溯，没有文件工具，只在 owner lane 里跑。
  - 读事实的工具：`timeline_query`（§读5.3）、messages、outbox、approvals（包括我改过的草稿和拒绝理由）、日历、matter 文件，以及 `self/` 里允许读的部分。
  - 写的工具：`outlook_submit`、`matter_update`、`review_submit`、`followup_set`、`habit_propose` 和 `rhythm_propose`（都只能提候选）。
- **lens**（受限 worker）：排盘要执行脚本，所以按 worker 的方式跑在 `sbot-w` 下，套 sandbox。
  - **网络全关**：它手上可能有出生信息，不能有任何外传通道。
  - 输入：需要生辰的方法才拿到 `config/self.yaml`（含换算好的 `chart_input`）和 `self/charts/` 的只读副本；都有对应镜头的 skill 和 `self/lens-notes/<lens>.md`。
  - 输出：用 `submit_reading` 交回统一格式的结果（§参1）。
